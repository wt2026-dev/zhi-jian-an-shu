# AI 真实效果评测报告

> **评测日期**：2026-09-14
> **评测模式**：真实 DashScope Key + 生产 API
> **复现命令**：`npx tsx scripts/ai-real-eval.ts`（需容器运行 + .env 已配置 Key）

---

## 一、两层口径说明

本报告评测的是**模型层**效果，不是降级层：

| 层 | 含义 | 本次是否评测 |
|---|---|---|
| **模型层** | 真实调用 DashScope API（qwen-plus / qwen-vl-max），评测模型生成质量 | ✅ 是 |
| **系统降级层** | 无 Key / 超时时自动切换规则引擎，评测降级契约（degraded 标记、不伪造） | ❌ 否（已有 `scripts/ai-eval.ts` 覆盖） |

两层互补：降级层确保"无网无 Key 也可靠"，模型层确保"有 Key 时真正有用"。

---

## 二、方法与样本

- **诊断评测**：15 条固定样本，来自种子知识库真实设备故障场景。对每条调用 `POST /api/v1/ai/diagnose`，body 含 `equipmentName`、`category:"旋转设备"`、`symptoms`。
- **视觉评测**：4 张图片（含 2 张占位图已核实），调用 `POST /api/v1/ai/vision-defect-detect`，传 `data:image/png;base64,{base64}` 前缀。
- **判定标准**：
  - 诊断：`success=true` + 非 degraded + 输出含期望关键词 + summary/probableCauses/recommendedActions/safetyPrecautions 四项非空
  - 视觉：`success=true` + 非 degraded + confidence ∈ [0,1] + summary 非空
- **失败处理**：任何失败如实记录原始输出，不重试、不改写、不润色。

## 七、局限说明

1. **诊断样本为固定场景**：15 条覆盖旋转设备常见故障，但不代表所有工业场景。实际效果取决于现场数据质量。
2. **视觉样本含占位图**：4 张中 2 张为非真实缺陷图，视觉评测验证的是链路完整性而非检测精度。
3. **单次评测无统计显著性**：模型输出具有随机性（temperature > 0），相同输入多次调用可能产生不同结果。如需统计显著性，需对每条样本重复 N 次并计算通过率分布。
4. **模型层 vs 降级层互补**：本报告仅评测模型层。降级层（无 Key / 超时场景）的确定性输出质量由 `scripts/ai-eval.ts`（12 条离线样本，零外部调用）保证。
5. **耗时受网络影响**：诊断耗时 20-33s，受阿里云 API 响应速度和网络延迟影响，不代表本地推理性能。
6. **Prompt 版本固定**：本次评测使用系统内置 prompt（v2.1.0），prompt 优化后效果可能进一步提升。

```bash
# 前置条件：容器已运行 + .env 已配置 DASHSCOPE_API_KEY
docker compose up -d

# 运行评测
npx tsx scripts/ai-real-eval.ts

# 查看原始输出
ls scratch/ai-real-eval-output/
```

评测结果 JSON 汇总输出到控制台，每条样本的完整模型响应保存在 `scratch/ai-real-eval-output/diag_XX.json` 和 `vision_XX.json`。
