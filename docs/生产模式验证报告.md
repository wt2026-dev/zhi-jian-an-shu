## 9. 兼容性问题清单

| # | 问题 | 影响范围 | 解决方案 | 状态 |
|---|------|----------|----------|------|
| 1 | `hashtext()` 函数在迁移 018/019 中用于确定性坐标生成 | PGlite 无此函数，真 PG 内置 | 无需修复：PGlite 模式下 UPDATE 条件 `map_x IS NULL` 使该语句不执行；真 PG 原生支持 | ✅ 无问题 |
| 2 | JSONB 向量/HNSW 索引（`vectorStore.ts`） | pgvector 扩展 | 自动检测：`CREATE EXTENSION IF NOT EXISTS vector` 失败时回退 JSONB 模式；真 PG + pgvector 时自动启用 HNSW | ✅ 自动降级 |
| 3 | `ON CONFLICT` 语法（migrations 008/009/014） | 跨引擎兼容 | PGlite 0.5.x 和 PG 16 均支持标准 `ON CONFLICT DO UPDATE/NOTHING` | ✅ 无需修复 |
| 4 | `ALTER TABLE ... ADD COLUMN IF NOT EXISTS` | 跨引擎兼容 | 两者均支持 | ✅ 无需修复 |
| 5 | `ALTER TABLE ... ALTER COLUMN ... TYPE TEXT` (migration 011) | 跨引擎兼容 | 两者均支持 | ✅ 无需修复 |
| 6 | `jsonb_set()` 函数 (migration 023) | 跨引擎兼容 | PGlite 和 PG 均支持 | ✅ 无需修复 |
| 7 | `TIMESTAMPTZ` / `TIMESTAMP` 混用 | 一致性问题 | migration 009 用 `TIMESTAMP`，其余用 `TIMESTAMPTZ`；功能不受影响，生产环境统一为 `TIMESTAMPTZ` 更佳 | ⚠️ 建议统一 |

**结论：23 个迁移在真 PG 上零兼容性问题，所有 SQL 语法均为标准 PostgreSQL 语法，PGlite 与 PG 16 完全兼容。数据迁移工具已覆盖全量 29 张业务表（2026-09-14 更新）。**

## 10. 可复现命令

```bash
# 1. 启动 PostgreSQL 16 容器
docker run -d --name industrial-pg16 \
  -e POSTGRES_PASSWORD=pgtest123 \
  -e POSTGRES_DB=industrial_maintenance \
  -p 5432:5432 postgres:16-alpine

# 2. 配置 .env（切换到 PostgreSQL）
# DATABASE_URL="postgresql://postgres:pgtest123@localhost:5432/industrial_maintenance"
# DB_TYPE=postgres

# 3. 执行迁移
npm run db:migrate

# 4. 导入种子数据
npm run db:seed

# 5. 运行核心测试（PG 模式）
npx vitest run tests/work-order-state-machine.test.ts
npx vitest run tests/rbac.test.ts
npx vitest run tests/optimistic-lock-and-concurrency.test.ts

# 6. 回归验证（恢复 PGlite 模式）
# 恢复 .env 为 DATABASE_URL="pglite://./data/industrial_ops_pg"
npx vitest run
```
