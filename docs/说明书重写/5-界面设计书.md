# 界面设计书

> 对应 §1 / §2 / §3 · 范围：设计语言 + 全局布局 + 关键页面 + 交互模式

## 设计起点

**工业暗色主题**：slate-950 深蓝灰底 + 青（#06b6d4）/琥珀（#f59e0b）/玫红（#f43f5e）/翠绿（#10b981）高对比强调色。兼顾工业现场强光可读与长时间操作护眼。强调色**不仅用于状态，也用于主操作按钮 / 选中态 / 焦点环**，让暗背景下"可点击"一眼可辨。

动效用 **motion 12**（`motion` 包，**不是 framer-motion**）—— 路径统一为 `import { motion, AnimatePresence } from 'motion/react'`。

## 3 关键页面布局

### 3.1 登录页 `LoginView`

居中卡片，工业暗色背景。用户名 / 密码输入框 + 9 个角色快捷选择按钮（演示账号一键填入）。登录按钮用青色高亮，密码错误显示玫红 toast。

### 3.2 驾驶舱首页 `CockpitDashboardView` / `DashboardView`

- 顶部 4 个 KPI 卡片（待处理工单 / 设备健康 / 安全合规 / AI 调用次数）
- 中部实时数据流（3D 车间缩略 + 工单流）
- 右侧最近活动 / 通知流

### 3.3 工单看板 `WorkOrdersView`

三列看板：待处理 → 进行中 → 已完成。每张卡片显示：工单编号、设备名称、优先级色条、创建时间、负责人头像。支持拖拽移动状态。

### 3.4 工单详情

左侧：工单基本信息（状态流转时间轴 + 评论）。右侧：关联作业票、巡检记录、AI 诊断结果。底部：操作记录。409 冲突时弹出橙色警告条，显示"数据已被修改，请刷新"。

### 3.5 巡检任务

日历视图 + 列表视图切换。已巡检项显示绿色对勾，异常项显示玫红警告。支持 WebRTC 扫码签到（`navigator.mediaDevices.getUserMedia`）。

### 3.6 作业票签署

全屏表单，顶部显示作业票类型标签。必填字段标红星，未填写时提交按钮禁用（灰色）。双人签名区：第一签名区完成后自动展开第二签名区。完成按钮变翠绿色。

### 3.7 LOTO 管理

设备拓扑图 + 锁具列表。已上锁设备显示紫色图标，解锁需扫码 + 密码双重验证。锁具颜色编码：红 = 动力锁、蓝 = 仪表锁、黄 = 安全锁。

### 3.8 AI 诊断页

左半屏：工单详情。右半屏：AI 诊断结果流式输出，逐字渲染。底部：知识库推荐（Top-5 相关文档卡片）。AI 不可用时显示琥珀色背景提示条 + 自动降级说明。

### 3.9 知识库

树形分类导航 + 列表内容。支持全文搜索 / 语义搜索切换。编辑器用 Markdown 格式，支持图片和代码块。RAG 检索结果显示相似度评分。

### 3.10 3D 车间可视化 `equipment3d/`

第一人称漫游（WASD + 鼠标）。故障设备红色高亮（脉冲环 + 引导虚线）。5 种彩层可独立开关（顶部图例条）：
- 故障环（玫红脉冲）
- 技师轨迹（青色虚线）
- 引导虚线（琥珀）
- 介质粒子（绿色粒子）
- 边界条件（紫色多边形）

设备单台特征化：每个设备用独立 GLB 模型 + 独立 `EQUIPMENT_GLB_MAP` 映射（**追加安全，重排不安全**）。

### 3.11 检修闯关 `GodotGameView`

`<iframe>` 嵌入 Godot 4.7 Web 导出（`/godot-game-2d/index.html`）。React 顶栏：
- 故障侦探 · 3D ← **遗留命名，新版是 2D，待清理**
- 引擎已连接 / 引擎未连接（健康指示）
- 设备数 / 关卡数 / 结构检查 / 操作员姓名

游戏内：HUD（生命 / 积分 / 计时）+ 设备标签 + 检修弹层（3 道小关键盘作答）+ 结算（星级 + 用时 + 正确率）。

### 3.12 数字人 AI 助手 `AiAssistantPanel`

右下角浮动球（56px，"庖"字印章式 + 琥珀虚线环）：
- **可拖动**（Pointer Capture，跨 iframe 也不卡，详见 §3.13）
- 点击展开卡片（340×420，slate 半透明 + backdrop-blur）
- 卡片头：数字人头像 + 角色名 + 在线状态
- 卡片体：消息流（Markdown 渲染）+ 输入框（Enter 发送）+ 麦克风 + 发送按钮
- 卡片操作：语音朗读开关、最小化（−）、关闭（×）

### 3.13 跨 iframe 拖拽（重要交互范式）

`AiAssistantPanel.tsx` 的悬浮球会压在 Godot iframe 上。**关键约束**：

- ❌ `onMouseDown + window.addEventListener('mousemove')` —— 划过 iframe 时父 window 收不到 mousemove，拖拽卡死
- ✅ `onPointerDown + e.currentTarget.setPointerCapture(e.pointerId)` —— 把后续 pointer 事件强制重定向到发起元素，跨 iframe 不丢事件
- ✅ window 监听用 `pointermove / pointerup / pointercancel`（Pointer Events 是鼠标 / 触摸 / 笔的超集）
- ✅ CSS `touchAction: 'none'` —— 移动端不滚屏

验收要点：拖拽脚本必须在带 iframe 的真实场景里测，dashboard 无 iframe 是测不出来的。

## 4 关键交互模式

### 4.1 AI 流式体验

```
用户点击"AI诊断"
  → 按钮变为加载态（旋转图标 + "诊断中..."）
  → 右侧结果区出现光标闪烁效果
  → 逐字渲染诊断结果（每 token 一个字符）
  → 渲染完成后显示置信度评分
  → 底部展开"推荐操作"卡片
```

### 4.2 表单防错 409

```
用户提交表单
  → 前端校验（必填 / 格式）
  → API 返回 409 VERSION_CONFLICT
  → 弹出橙色警告对话框
  → 显示冲突详情（谁在何时修改了什么）
  → 提供"查看最新数据"按钮
  → 用户确认后刷新表单（保留已填内容）
```

### 4.3 作业票签署流程

```
第一签名人完成签名
  → 签名区缩小为已签状态（头像 + 时间）
  → 第二签名区从右侧滑入
  → 第二签名人签名
  → 状态变为"已签署"（翠绿色）
  → 自动触发关联工单状态流转
```

### 4.4 通知推送

```
事件发生（工单创建 / 作业票签署 / AI 诊断完成）
  → 服务端推送 WebSocket 消息
  → 浏览器右上角弹出通知卡片
  → 3 秒后自动收起到通知中心
  → 通知中心红点 + 未读计数
```
