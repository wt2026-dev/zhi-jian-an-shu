# 拍摄脚本

> 适用版本：2026-09 校准版 · 与 `docs/说明书重写/{1..6}*.md` 对齐 · 全部时长 ~6 分钟

## 作品定位

本作品面向流程制造企业，解决设备维修管理中信息孤岛、流程断裂、知识流失三大痛点。通过数字化手段实现从巡检发现 → 报修 → 调度 → 维修 → 验收 → 知识沉淀的全链路闭环。在传统 7 角色（巡检 / 报修 / 调度 / 维修 / 安全 / 质检 / 知识）协同之外，新增 3 个差异化模块：
- **3D 车间可视化层**（第一人称漫游 + 设备单台特征化）
- **检修闯关（Godot 4 Web 导出，2D 横版）** —— 员工培训 / 流程演练
- **数字人 AI 助手**（3D VRM + 语音播报 + 跨页面拖拽）

## 1 拍摄准备

### 1.1 环境准备

| 项目 | 要求 |
|------|------|
| 操作系统 | Windows 10/11 或 macOS |
| Docker | Docker Desktop 最新版（生产演示）或 `npm install` + `npm run dev`（开发） |
| 浏览器 | Chrome 120+（无插件干扰，关闭书签栏 / 扩展图标） |
| 分辨率 | 1920×1080（录屏）|
| 网络 | 稳定连接（AI 服务依赖 DashScope OpenAI 兼容端点） |

### 1.2 启动命令

```bash
# 方式 A：Docker（生产演示）
docker compose up -d

# 方式 B：本地开发
npm install && npm run dev
```

浏览器打开 `http://localhost:3000`

### 1.3 测试数据

系统预置以下演示数据：
- 30 张业务表（25 个幂等迁移文件初始化）
- 9 个演示账号（admin / manager / tech1 / tech2 / inspector / inspector2 / operator / operator2 / archivist）
- 示例设备、工单、巡检计划、知识条目
- 16 台设备的 2D 检修闯关关卡
- 3 套数字人形象（zhang / li / zhi）

## 2 十二个分镜

### 分镜1：开场（30秒）

**画面**：工业厂区远景 → 反应釜特写 → 温度仪表盘异常跳动

**解说**：
> 冶金车间反应釜温度异常，操作工发现传感器读数超过阈值。传统模式下，纸质工单流转慢、信息传递易失真、维修经验随人员流动而丢失。我们用数字化手段，让每一个环节都可追踪、可审计、可沉淀。

**时间**：00:00 - 00:30

---

**画面**：终端窗口输入启动命令 → 浏览器打开 → 登录页

**解说**：
> 系统基于 Docker 容器化部署，一条命令启动。打开浏览器，输入 localhost:3000，进入工业风暗色主题登录界面。

**时间**：00:30 - 00:50

**操作**：
```bash
docker compose up -d
```

**画面**：操作工登录 → 新建工单 → 填写表单 → 提交 → 看板显示新工单

**解说**：
> 操作工登录系统，点击新建工单。选择故障设备，填写故障描述。系统自动检查 15 分钟防重复，确保同一设备不会被重复报修。工单编号 WO-20260921-001 自动生成，状态流转至待派工。

**时间**：00:50 - 01:30

**关键操作**：
- 使用 `operator` 账号登录

- 工单出现在看板"待处理"列

### 分镜4：3D 车间漫游（40秒）

**画面**：进入 3D 场景 → 第一人称漫游 → 故障设备红色高亮 → 关闭某层彩层 → 设备详情

**解说**：
> 我们把车间搬进了浏览器。第一人称漫游，从第一人称视角审视整套设备。故障设备被玫红脉冲环高亮，并配琥珀色引导虚线把视线引过去。顶部图例条可以独立开关 5 种彩层（故障环 / 技师轨迹 / 引导虚线 / 介质粒子 / 安全边界），避免视觉过载。每个设备的 3D 模型都做了差异化特征化，避免"克隆出复制粘贴品质"。

**时间**：01:30 - 02:10

**关键操作**：
- 点击左侧导航"3D 场景"
- WASD 漫游到设备区
- 切换顶部图例条开关（关掉技师轨迹）
- 点击某个设备查看详情

---

### 分镜5：作业票签署（40秒）

**画面**：创建作业票 → 选择类型 → 填写内容 → 第一人签署 → 第二人签署 → 状态变为已签署

**解说**：
> 高危作业需要双人会签。创建动火作业票，安全员确认安全措施后签署，车间主任复核后签署。两道确认，确保安全措施到位。LOTO 锁具同步登记，设备进入隔离状态。

**时间**：02:10 - 02:50

**关键操作**：
- 在工单详情页点击"创建作业票"
- 选择"动火作业"
- 填写安全措施
- 使用 `manager` 账号签署（guardian_approval JSONB 写入）
- 第二人签署完成（supervisor_approval JSONB 写入，status='signed'）

---

### 分镜6：AI 诊断 + SSE 流式（50秒）

**画面**：点击 AI 诊断按钮 → 流式输出结果 → 置信度评分 → 知识库推荐

**解说**：
> 系统集成 24 项 AI 能力，分三层架构 + 多模态：基础层进行故障分类和严重度评估，分析层提供根因分析和维修方案推荐，决策层生成应急预案和资源调度建议，多模态层支持视觉缺陷检测、视频分析、语音转文本、AI 流水线。诊断结果通过 SSE 流式传输，逐字呈现分析过程。系统自动匹配知识库中的相关案例，为维修决策提供参考。

**时间**：02:50 - 03:40

**关键操作**：
- 在工单详情页点击"AI 诊断"
- 观察右侧结果区流式输出（`POST /api/v1/ai/chat/stream`）
- 查看置信度评分
- 浏览底部知识库推荐（来自 `/api/v1/ai/rag-search`）

---

### 分镜7：数字人 AI 助手（40秒）

**画面**：右下角悬浮 AI 球 → 拖动到页面中央 → 点击展开 → 提问 → 回答流式输出 → 关闭

**解说**：
> 右下角的琥珀色印章式 AI 球，可以拖动到屏幕任何位置（即使拖进 3D 场景的 iframe 也不卡）。点击展开为 340×420 的助手卡片，有 3D 数字人形象（张工 / 李工 / 智工）、语音播报、Markdown 渲染的回答流。整套跨页面、跨 iframe 拖拽都需要 Pointer Capture 才能避免事件被 iframe 切断。

**时间**：03:40 - 04:20

**关键操作**：
- 拖动右下角悬浮 AI 球（按 Pointer Capture）到屏幕中央
- 点击展开卡片
- 输入"离心泵常见的故障类型有哪些？"
- 观察流式回答
- 点 × 关闭

### 分镜8：检修闯关（40秒）

**画面**：进入检修闯关 → 角色移动 → 跳上设备 → 按 E 触发检修 → 3 道小关 → 结算

**解说**：
> 这是给一线员工准备的检修闯关小游戏：2D 横版工厂车间，16 台设备沿地面排列。玩家扮演黄安全帽 + 蓝工装的工程师，用 A/D 移动、空格跳跃，走到故障设备旁按 E 触发检修。每台设备的检修有 3 道小关（选工具 / 安全判断 / 排序），全部键盘作答（数字键 / Y/N）。通关有星级评定 + 用时 + 正确率。整套用 Godot 4.7 做的，导出 Web 后用 iframe 嵌入 React。

**时间**：04:20 - 05:00

**关键操作**：
- 进入"检修闯关"
- A/D 移动角色到第一台故障设备旁
- 空格起跳 / 跨越障碍
- 按 E 弹出检修面板
- 数字键答选工具题，Y/N 答安全判断题
- 通关弹出结算面板

---

### 分镜9：知识沉淀（30秒）

**画面**：知识库页面 → 搜索故障案例 → 查看向量匹配结果 → 新建知识条目

**解说**：

**时间**：05:00 - 05:30

**关键操作**：
- 使用 `archivist` 账号登录
- 点击"知识库"
- 搜索"反应釜温度异常"
- 查看匹配结果（Top-5 + 相似度评分）
- 新建一条知识条目

## 3 录制注意事项

### 3.1 操作规范

- 每个操作步骤之间停顿 2-3 秒，便于后期剪辑
- 鼠标移动平稳，避免快速晃动
- 点击操作前稍作悬停，让观众看清按钮位置
- 表单填写使用真实感数据（设备名称、故障描述）
- Godot 游戏环节要给 3-5 秒解压时间

### 3.2 画面规范

- 浏览器全屏显示，隐藏书签栏和扩展图标
- 字体大小适中，确保 1080p 下清晰可读
- 暗色主题下避免高亮内容刺眼
- 关键操作区域可用录屏工具画圈标注

### 3.3 解说规范

- 语速适中，每分钟 180-200 字
- 关键术语准确（**注意：是 SSE / RAG / LOTO / pgvector，不是 dashscope-sdk 而是 OpenAI 兼容**）
- 操作步骤与解说同步
- 结尾总结数据准确：30 张表 / 25 迁移 / 24 项 AI / 89 测试文件 / 1069 用例

### 3.4 常见问题

| 问题 | 预防措施 |
|------|---------|
| AI 诊断无响应 | 提前测试网络，准备离线演示方案（降级到本地规则）|
| Godot 游戏加载慢 | 提前加载一次预热 |
| 页面加载慢 | 清除缓存，关闭无关程序 |
| 登录失败 | 确认演示账号密码正确 |
| 截图模糊 | 使用系统原生截图，避免压缩 |
| 跨 iframe 拖拽卡死 | 验收必须含 iframe 场景（参考 `docs/说明书重写/3-详细设计说明书.md` §7）|
