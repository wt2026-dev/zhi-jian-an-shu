# 数据库设计说明书

> 对应 §1 / §2 · 范围：迁移策略 + 表结构 + 索引 + 完整性约束

## 数据架构起点

**25 个幂等迁移**（`src/db/migrations/001-*.sql` 到 `025-*.sql`），**PGlite 与 PostgreSQL 双适配**，通过 `DB_TYPE` 环境变量切换。`runMigrations()` 读 `.sql` 文件按序执行，每条语句单独 `try`/`catch`，吞掉 `already exists` 类错误保证重启 / 复用同一目录不炸。**没有 `schema_migrations` 表**（老文档说有的 —— 那是设计目标，实现靠 `CREATE TABLE IF NOT EXISTS` + 吞错误）。pgvector 可用时 `knowledge_embeddings.embedding` 从 JSONB 升级到 `vector(1024)` + HNSW 索引，否则回退到 JSONB 余弦相似度 O(n) 扫描。

```typescript
// src/db/db.ts —— 迁移执行核心
async function runMigrations(adapter) {
  const files = (await fs.readdir(MIGRATIONS_DIR)).filter(f => f.endsWith('.sql')).sort();
  for (const file of files) {
    const sql = await fs.readFile(path.join(MIGRATIONS_DIR, file), 'utf-8');
    const stmts = sql.split(/;\s*$/m).map(s => s.trim()).filter(Boolean);
    for (const stmt of stmts) {
      try { await adapter.query(stmt); }
      catch (e) {
        if (!/already exists/i.test(String(e.message))) throw e; // 吞 "already exists"
      }
    }
  }
}
```

## 3 核心表结构详解

### 3.1 work_orders（工单主表）

```sql
CREATE TABLE work_orders (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  order_no VARCHAR(32) UNIQUE NOT NULL,
  title VARCHAR(200) NOT NULL,
  description TEXT,
  equipment_id UUID REFERENCES equipments(id),
  fault_type VARCHAR(50),
  priority VARCHAR(10) NOT NULL DEFAULT 'medium',  -- low/medium/high/critical
  status VARCHAR(20) NOT NULL DEFAULT 'draft',
  creator UUID REFERENCES users(id),
  assignee UUID REFERENCES users(id),
  source VARCHAR(50),                              -- 013 迁移新增：巡检/手动/AI
  safety_requirements JSONB DEFAULT '{}',
  repair_log JSONB DEFAULT '{}',
  acceptance JSONB DEFAULT '{}',
  version INTEGER NOT NULL DEFAULT 1,
  created_timestamp BIGINT,
  created_at TIMESTAMP DEFAULT NOW(),
  updated_at TIMESTAMP DEFAULT NOW()
);

CREATE INDEX idx_work_orders_status ON work_orders(status);
CREATE INDEX idx_work_orders_equipment ON work_orders(equipment_id);
CREATE INDEX idx_work_orders_creator ON work_orders(creator);
CREATE INDEX idx_work_orders_created_at ON work_orders(created_at DESC);
```

### 3.2 equipment_telemetry（设备遥测）

```sql
CREATE TABLE equipment_telemetry (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  equipment_id UUID REFERENCES equipments(id),
  metric_name VARCHAR(50) NOT NULL,    -- temperature/pressure/vibration/current/flow/speed
  metric_value DECIMAL(12,4) NOT NULL,
  unit VARCHAR(20) NOT NULL,           -- ℃/MPa/mm/s/A/L·min⁻¹/rpm
  quality VARCHAR(10) DEFAULT 'good',  -- good/bad/uncertain
  source VARCHAR(50) DEFAULT 'manual', -- manual/sensor/scada
  recorded_at TIMESTAMP NOT NULL DEFAULT NOW()
);

CREATE INDEX idx_telemetry_equipment ON equipment_telemetry(equipment_id);
CREATE INDEX idx_telemetry_name_time ON equipment_telemetry(metric_name, recorded_at DESC);
```

**6 个遥测维度**：温度（℃）、压力（MPa）、振动（mm/s）、电流（A）、流量（L·min⁻¹）、转速（rpm）。

### 3.3 knowledge_embeddings（知识向量）

```sql
-- 默认（开发 PGlite 无 pgvector）
CREATE TABLE knowledge_embeddings (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  article_id UUID REFERENCES knowledge_articles(id),
  embedding JSONB,                              -- 存成 [0.12, -0.34, ...] 数组
  model VARCHAR(50) NOT NULL DEFAULT 'text-embedding-v3',
  chunk_text TEXT,
  created_at TIMESTAMP DEFAULT NOW()
);
```

pgvector 可用时（生产 PostgreSQL）通过 `vectorStore.ensureEmbeddingColumn()` 在线升级：

```sql
ALTER TABLE knowledge_embeddings ALTER COLUMN embedding TYPE vector(1024) USING embedding::vector(1024);
CREATE INDEX idx_embeddings_vector ON knowledge_embeddings USING hnsw (embedding vector_cosine_ops);
```

**嵌入维度 1024**（不是 1536）、**模型 `text-embedding-v3`**（不是 v2）。

### 3.4 loto_locks（LOTO 锁具）

```sql
CREATE TABLE loto_locks (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  lock_no VARCHAR(20) UNIQUE NOT NULL,   -- LOTO-001
  equipment_id UUID REFERENCES equipments(id),
  status VARCHAR(20) DEFAULT 'available', -- available/locked/lost
  created_at TIMESTAMP DEFAULT NOW()
);
```

## 4 索引与完整性

### 4.1 全局索引策略

- 所有外键字段自动建索引
- 时间字段降序索引（列表查询按时间倒序）
- 状态字段索引（筛选）
- JSONB 字段 GIN 索引（`work_orders.safety_requirements / repair_log / acceptance`、`safety_permits.*_approval`、`users.certifications`）
- 向量字段 HNSW 索引（pgvector 可用时）

### 4.2 完整性约束

```sql
-- 用户名唯一
ALTER TABLE users ADD CONSTRAINT uq_users_username UNIQUE (username);

-- 工单编号唯一
ALTER TABLE work_orders ADD CONSTRAINT uq_work_orders_order_no UNIQUE (order_no);

-- 锁具编号唯一
ALTER TABLE loto_locks ADD CONSTRAINT uq_loto_locks_lock_no UNIQUE (lock_no);

-- 作业票状态枚举
ALTER TABLE safety_permits ADD CONSTRAINT ck_permit_status
  CHECK (status IN ('pending', 'signed', 'rejected', 'expired'));

-- 遥测值非负
ALTER TABLE equipment_telemetry ADD CONSTRAINT ck_telemetry_value
  CHECK (metric_value >= 0);

-- LOTO 锁状态枚举
ALTER TABLE loto_locks ADD CONSTRAINT ck_lock_status
  CHECK (status IN ('available', 'locked', 'lost'));

-- 优先级枚举
ALTER TABLE work_orders ADD CONSTRAINT ck_priority
  CHECK (priority IN ('low', 'medium', 'high', 'critical'));
```

## 5 备份与一致性

- `data/.pglite-active.json` 记录当前活跃的 PGlite 目录（PID + 启动时间戳仲裁多 app 实例）
- `openPgliteWithFallback()` 检测到损坏时回退到最近一次成功的快照（`data.bak-*`）
- `data.bak-{timestamp}` 目录：每次启动前自动备份当前 `data/`，保留最近 3 个
- 测试库 (`TEST_DB=true`) 是**内存库**，不能用来验"历史还在吗"

详细故障恢复路径见 `docs/history/修复报告-服务猝死与数据库恢复.md`。
