# 概要设计说明书

## 架构设计起点

React 19 单页应用 + Express API 同进程部署，PGlite 嵌入式 PostgreSQL，DashScope qwen-plus/qwen-vl-max 提供 AI 能力。无外部数据库依赖，一条命令启动。

## 3 关键设计

### 3.1 工单状态机

```javascript
const ALLOWED_TRANSITIONS = {
  draft:      ['submitted'],
  submitted:  ['assigned', 'cancelled'],
  assigned:   ['in_progress', 'cancelled'],
  in_progress:['pending_review', 'on_hold'],
  pending_review: ['completed', 'in_progress'],
  on_hold:    ['in_progress'],
  completed:  ['closed'],
  closed:     [],
  cancelled:  []
};
```

状态流转时校验 `nextStatus ∈ ALLOWED_TRANSITIONS[currentStatus]`，不合法返回 `400 INVALID_TRANSITION`。

### 3.2 乐观锁与 409 处理

```javascript
// 每次更新携带 version
UPDATE work_orders 
SET status=?, version=version+1, updated_at=NOW()
WHERE id=? AND version=?

// 影响行数为 0 → 409 VERSION_CONFLICT
if (affectedRows === 0) {
  return res.status(409).json({ 
    code: 'VERSION_CONFLICT',
    message: '数据已被其他人修改，请刷新后重试'
  });
}
```

### 3.3 SSE 协议设计

AI 诊断接口使用 Server-Sent Events 流式返回：

```
GET /api/v1/ai/diagnose/:orderId

Content-Type: text/event-stream
Cache-Control: no-cache

data: {"type":"token","content":"根据"}
data: {"type":"token","content":"传感器"}
data: {"type":"result","analysis":"根因是...","confidence":0.87}
data: [DONE]
```

前端通过 `EventSource` 接收，逐字渲染诊断结果。

### 3.4 AI 降级机制

当 DashScope API 不可用时，系统自动降级：

| 场景 | 降级策略 |
|------|---------|
| API 超时（>30s） | 返回缓存的最近诊断结果 |
| API 限流（429） | 排队等待，前端显示进度条 |
| API 密钥失效 | 返回本地规则引擎结果 |
| 网络断开 | 离线模式，仅展示历史数据 |

降级日志写入 `ai_analysis_log` 表，便于后续排查。

### 3.5 安全鉴权基线

全局 API 鉴权中间件执行流程：

```
请求 → JWT 验证 → 角色解析 → 权限码匹配 → 路由处理
         ↓          ↓           ↓
      401 无效    403 禁止     403 无权限
```

JWT Payload 包含 `userId`、`role`、`permissions[]`，有效期 24 小时。

## 4 接口规范

### 4.1 统一响应格式

```json
{
  "success": true,
  "data": {},
  "message": "操作成功",
  "timestamp": "2026-09-14T05:47:00Z"
}
```

### 4.2 错误码表

| HTTP状态码 | 错误码 | 说明 |
|-----------|--------|------|
| 400 | INVALID_TRANSITION | 工单状态流转不合法 |
| 400 | DUPLICATE_ORDER | 15分钟内重复报修 |
| 401 | UNAUTHORIZED | JWT无效或过期 |
| 403 | FORBIDDEN | 权限不足 |
| 404 | NOT_FOUND | 资源不存在 |
| 409 | VERSION_CONFLICT | 乐观锁冲突 |
| 429 | RATE_LIMITED | AI服务限流 |
| 500 | INTERNAL_ERROR | 服务器内部错误 |

## 5 部署架构

```yaml
# docker-compose.yml
services:
  app:
    build: .
    ports:
      - "3000:3000"
    volumes:
      - pgdata:/app/data  # PGlite 持久化
    environment:
      - DASHSCOPE_API_KEY=${DASHSCOPE_API_KEY}
      - JWT_SECRET=${JWT_SECRET}
```

单容器部署，`docker compose up -d` 一条命令启动。PGlite 数据文件持久化到 `pgdata` 卷。
