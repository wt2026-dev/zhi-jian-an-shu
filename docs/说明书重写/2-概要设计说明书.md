# 概要设计说明书

> 对应 §1 需求说明书 · 范围：架构全景 / 模块划分 / 关键设计 / 接口规范 / 部署

## 架构设计起点

**单进程双形态**：开发与生产共用一份代码，`npm run dev` = `tsx server.ts`（Vite 中间件模式嵌同进程），生产用 `docker-compose.yml` 单容器；前端热更新无需重启服务。**无外部数据库依赖**，通过 `DB_TYPE` 环境变量在 PGlite（开发 / 测试）与 PostgreSQL（生产）之间切换。

AI 走 DashScope 提供的 OpenAI 兼容端点，**客户端用 `openai` SDK 7.10**（不引入 `dashscope-sdk`）。`aiModelRouter` 支持多候选模型 + 自动 failover。Vite 6.2 + React 19 + three.js 0.186 + motion 12（**不是 framer-motion**）构建前端。

## 3 关键设计

### 3.1 工单状态机

```javascript
const ALLOWED_TRANSITIONS = {
  draft:           ['submitted'],
  submitted:       ['assigned', 'cancelled'],
  assigned:        ['in_progress', 'cancelled'],
  in_progress:     ['pending_review', 'on_hold'],
  pending_review:  ['completed', 'in_progress'],
  on_hold:         ['in_progress'],
  completed:       ['closed'],
  closed:          [],
  cancelled:       []
};
```

状态流转校验 `nextStatus ∈ ALLOWED_TRANSITIONS[currentStatus]`，不合法返回 `400 INVALID_TRANSITION`。

### 3.2 乐观锁与 409 处理

```sql
UPDATE work_orders
SET <fields>, version = version + 1, updated_at = NOW()
WHERE id = $1 AND version = $2
```

影响行数为 0 → 返回 `409 VERSION_CONFLICT { code: 'VERSION_CONFLICT', message: '数据已被其他人修改，请刷新后重试' }`。前端自研 `queryClient` 监听 409，回滚乐观缓存 + toast 提示。

### 3.3 防重复提交

15 分钟窗口内同 creator + 同 equipment + 同 fault_type 报修：

```sql
SELECT id, order_no FROM work_orders
WHERE creator = $1 AND equipment_id = $2 AND fault_type = $3
  AND created_at > NOW() - INTERVAL '15 minutes'
  AND status NOT IN ('cancelled', 'closed')
```

命中 → `409 DUPLICATE_ORDER`，附带已有工单链接。

### 3.4 SSE 协议设计

AI 流式接口 `POST /api/v1/ai/chat/stream`（**不是 GET**），Header：

```
Content-Type: text/event-stream
Cache-Control: no-cache
Connection: keep-alive
```

事件：
```
data: {"type":"token","content":"根据"}
data: {"type":"token","content":"传感器"}
data: {"type":"result","analysis":"根因是...","confidence":0.87}
data: [DONE]
```

前端 `EventSource`（或 fetch + ReadableStream）逐字渲染。AI 流水线（`/api/v1/ai/pipeline/:id/stream`）输出多步骤任务进展，每步独立 `step-start / step-progress / step-end` 事件。

### 3.5 AI 降级机制（4 层）

| 场景 | 降级策略 | 触发位置 |
|------|---------|---------|
| API 超时 > 30s | 返回 `utils/aiCache.ts` 的 LRU+TTL 缓存 | `aiClient` |
| 429 限流 | 排队等待 + 前端进度条 | `rateLimit` 中间件（60/min/IP） |
| 密钥失效 | 切换到 `aiModelRouter` 备选模型 | `aiModelRouter` |
| 网络断开 | 离线模式 + 仅展示历史数据 | 客户端重试退避 |
| 日预算耗尽 | 阻断新调用 | `dailyBudget` 中间件 |

降级日志写入 `ai_analysis_log.degraded=true`，便于复盘。

### 3.6 安全鉴权基线

```
请求 → globalAuthGuard（白名单：/login /health）
     → JWT 验证 → 角色解析 → 权限码匹配 → 路由处理
                   ↓          ↓           ↓
                401 无效    403 禁止     403 无权限
```

JWT Payload：`{ userId, role, permissions[], iat, exp }`，有效期 24 小时。密码 bcrypt 哈希（10 rounds）。Helmet CSP 锁定外联脚本 / 样式来源。CORS 限制 origin（默认仅本地 / 部署域名）。

### 3.7 Godot Web 嵌入 + postMessage 双向桥

`godot-game/` / `godot-game-2d/` / `godot-game-maze/` 三套独立 Godot 4.7 工程，各自 `--export-release "Web"` 到 `public/godot-game*/index.html`。`src/components/game/GodotGameView.tsx` 等用 `<iframe>` 嵌入，`export_presets.cfg` 的 `html/head_include` 注入：

```javascript
window.__godotInbox = [];
window.__godotPost = (o) => parent.postMessage(JSON.stringify(o), '*');
window.addEventListener('message', (e) => {
  try { window.__godotInbox.push(JSON.parse(e.data)); } catch {}
});
```

Godot 端 `JavaScriptBridge` 轮询 `window.__godotInbox.shift()`，发送时 `parent.__godotPost(payload)`。

**跨 iframe 拖拽**（悬浮 AI 球）：父 `window.addEventListener('pointermove')` 会被 iframe 切断，必须用 `setPointerCapture` 把后续事件强制重定向到发起元素（`AiAssistantPanel.tsx`）。

## 4 接口规范

### 4.1 统一响应格式

```json
{
  "success": true,
  "data": {},
  "message": "操作成功",
  "timestamp": "2026-09-14T05:47:00Z"
}
```

### 4.2 错误码表

| HTTP | code | 说明 |
|------|------|------|
| 400 | `INVALID_TRANSITION` | 工单状态流转不合法 |
| 400 | `DUPLICATE_ORDER` | 15 分钟内重复报修 |
| 401 | `UNAUTHORIZED` | JWT 无效或过期 |
| 403 | `FORBIDDEN` | 权限不足 |
| 404 | `NOT_FOUND` | 资源不存在 |
| 409 | `VERSION_CONFLICT` | 乐观锁冲突 |
| 409 | `DUPLICATE_ORDER` | 防重复命中 |
| 429 | `RATE_LIMITED` | AI 服务限流 |
| 502 | `AI_PARSE_ERROR` | AI 响应格式异常 |
| 500 | `INTERNAL_ERROR` | 服务器内部错误 |

## 5 部署架构

```yaml
# docker-compose.yml
services:
  app:
    build: .
    ports:
      - "3000:3000"
    volumes:
      - pgdata:/app/data         # PGlite 持久化
      - uploads:/app/public/uploads
      - videos:/app/public/videos
    environment:
      - DASHSCOPE_API_KEY=${DASHSCOPE_API_KEY}
      - JWT_SECRET=${JWT_SECRET}
      - DB_TYPE=pglite            # 或 postgres
```

单容器部署，`docker compose up -d` 一条命令启动。PGlite 数据文件持久化到 `pgdata` 卷。Godot Web 导出产物（`public/godot-game*/`）在镜像构建时 copy。
