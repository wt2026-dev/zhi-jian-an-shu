# 功能需求说明书

> 比赛作品：工业设备智能检修一体化平台（Industrial Equipment Intelligent Maintenance Platform, IMP）
> 适用版本：2026-09 校准版（与 `docs/口径核对清单.md` / `CHANGELOG.md` 对齐）

## 场景驱动的需求定义

冶金车间反应釜温度异常：操作工发现温度传感器读数超过阈值，扫码报修，系统自动生成高危作业票，触发双人会签 + LOTO 隔离流程，检修工单流转闭环，AI 诊断辅助生成维修建议，故障经验沉淀至知识库。整个链条涉及巡检、报修、调度、维修、安全、质检、知识管理七个角色协同。

围绕这个核心场景，系统向上延伸出 3D 车间可视化层（第一人称巡检 + 故障定位）、2D 检修闯关（Godot 4 Web 导出，嵌入 React iframe）、俯视迷宫（Godot 4 Web 导出，操作流程演练）、数字人 AI 助手（3D VRM 形象 + 语音播报）、AI 流水线（诊断 / 复盘 / 视频生成的多步骤任务链）。

## 1 角色与权限矩阵

系统采用 RBAC 模型，权限码格式 `module:action`，单一真源 `src/utils/rbac.ts`（菜单口径在 `src/components/layout/navConfig.ts`，**判定不许就地写**）。admin 角色恒放行。

| 角色 | 权限码集合（节选） | 典型操作 |
|------|----------------|---------|
| **admin**（系统管理员） | `*:*` | 全部权限，含用户管理、AI 模型配置 |
| **manager**（车间主任） | `order:read,write,close` `ticket:approve` `report:read` | 工单审批、作业票审批、报表查看 |
| **tech1**（检修工 - 主修） | `order:read,work,comment` `ticket:sign` `ai:diagnose` | 工单接单、执行维修、签名确认 |
| **tech2**（检修工 - 副修） | `order:read,work,comment` `ticket:sign` | 工单执行、副签 |
| **inspector / inspector2**（巡检员） | `inspection:read,write` `order:create` | 巡检记录、创建报修工单 |
| **operator / operator2**（操作工） | `order:create,read` `ticket:create` | 报修、查看进度、创建作业票 |
| **archivist**（知识管理员） | `knowledge:read,write,delete` `rag:query` | 知识库维护、RAG 检索 |

**校验位置**：每个 API 路由入口经 `globalAuthGuard` 中间件校验 `req.user.role` → 权限码集合，未匹配返回 `403 FORBIDDEN`。前端通过 `rbac.ts` 的 `can(role, 'module:action')` 双重校验，避免在未授权视图里渲染操作按钮。

## 2 功能需求清单（FR-01 ~ FR-09）

### FR-01 工单全生命周期管理

**编号规则**：`WO-{YYYYMMDD}-{SEQ}`，序号每日重置。

**状态机（`src/utils/orderStatus.ts`）**：
```
draft → submitted → assigned → in_progress → pending_review → completed → closed
                  ↘ cancelled                    ↘ on_hold ↗
```

**防重复提交**：同一操作工 15 分钟内对同一设备同一故障类型提交工单，返回 `409 DUPLICATE_ORDER`，前端弹出已有工单链接。

**乐观锁**：每次更新携带 `version`，SQL `WHERE id=? AND version=?`，匹配失败返回 `409 VERSION_CONFLICT`，前端回滚 TanStack Query 缓存并 toast。

> 注：上版文档写 "TanStack Query"，本项目实际只装 `@tanstack/react-virtual`（虚拟列表），无 TanStack Query，缓存由自研 `queryClient`（`src/utils/queryClient.ts`）+ 失效刷新承担。

### FR-02 巡检计划与执行

巡检计划支持按班次（早 / 中 / 晚）、设备类型、巡检路线配置。巡检员手持终端扫码签到（WebRTC 摄像头），系统记录 GPS 坐标与时间戳。异常项自动关联报修工单。

### FR-03 六类作业票 + 双人会签

| 作业票类型 | 必签角色 | 关联 LOTO |
|-----------|---------|---------|
| 动火作业 | 安全员 + 车间主任 | 是 |
| 受限空间 | 安全员 + 技术主管 | 是 |
| 高处作业 | 安全员 + 车间主任 | 是 |
| 临时用电 | 安全员 + 电气主管 | 否 |
| 吊装作业 | 安全员 + 车间主任 | 是 |
| 盲板抽堵 | 安全员 + 技术主管 | 是 |

每类作业票包含：作业单位、作业内容、风险等级（低 / 中 / 高 / 极高）、安全措施列表、双人签名时间戳。LOTO 锁具编号录入 `loto_locks` 表。

### FR-04 设备遥测与预警

6 个遥测维度：温度、压力、振动、电流、流量、转速。数据存入 `equipment_telemetry`，字段含 `metric_name / metric_value / unit / quality / source / recorded_at`。超阈值自动触发预警工单（**注：电流 / 电压 / 压力无前端阈值模板，全部走服务端规则**）。

### FR-05 3D 车间可视化层

`src/components/equipment3d/`：
- 第一人称车间漫游（WASD + 鼠标）
- 故障设备红色高亮（脉冲环 + 引导虚线）
- 设备单台特征化（每个 GLB 模型独立映射，避免"克隆出复制粘贴品质"）
- 5 种彩层可独立开关（故障环 / 技师轨迹 / 引导虚线 / 介质粒子 / 安全边界）

### FR-06 检修闯关（Godot 4 Web 导出）

`godot-game-2d/` 工程，导出至 `public/godot-game-2d/`。`src/components/game/GodotGameView.tsx` 用 `<iframe>` + postMessage 双向桥嵌入 React。3 关卡（新手入职 / 紧急抢修 / 故障解谜 / BOSS 战），每关含选工具 / 安全判断 / 排序 3 道小关。结算星级 + 用时 + 正确率 postMessage 回传 React。

> 旧版 Canvas 版本（`MasterGameView` / `MaintenanceGameView` / `platformerEngine.ts` 等）**保留为降级 fallback**，新版本不被引用。

### FR-07 AI 诊断 + 流水线

24 个 AI 接口（`src/server/routes/ai.ts`），分三层：

| 层级 | 数量 | 典型能力 | 路径前缀 |
|------|------|---------|---------|
| 基础层 | 5 | 故障分类、严重度评估、关键词提取、工单摘要、设备状态解读 | `/api/v1/ai/chat` |
| 分析层 | 10 | 根因分析、维修方案推荐、备件预测、关联故障发现、趋势预警、知识匹配、风险评估、效率分析、成本估算、方案对比 | `/api/v1/ai/diagnose`、`/api/v1/ai/rag-search`、`/api/v1/ai/multimodal-search` |
| 决策层 | 5 | 维修决策树、应急预案生成、资源调度建议、停机损失评估、改进建议 | `/api/v1/ai/suggest-followups`、`/api/v1/ai/safety-risk-assessment`、`/api/v1/ai/recommend-assignee` |
| 多模态 | 4 | 视觉缺陷检测、语音转文本、视频分析、AI 流水线（SSE 流式步骤） | `/api/v1/ai/vision-defect-detect`、`/api/v1/ai/speech-to-text`、`/api/v1/ai/video-analysis`、`/api/v1/ai/pipeline` |

**SSE 流式输出**：`POST /api/v1/ai/chat/stream`（不是 GET），按 token 推送，逐字渲染。AI 流水线（`/api/v1/ai/pipeline`）用 SSE 输出多步骤任务进展。

**AI 降级**：
- API 超时（>30s）→ 返回缓存（`utils/aiCache.ts`，LRU+TTL）
- 429 限流 → 排队等待
- 密钥失效 → 本地规则引擎兜底
- 网络断开 → 离线模式（标记 `degraded=true`）
- 日预算耗尽 → 阻断新调用，已发出累计运行调用

### FR-08 知识库与 RAG

故障案例、维修手册、安全规程存入 `knowledge_articles`，向量化到 `knowledge_embeddings.embedding`：
- 默认存储 JSONB（开发环境 / PGlite 无 pgvector 时降级）
- pgvector 可用时升级为 `vector(1024)` + HNSW 索引
- 嵌入模型 `text-embedding-v3`（**不是 v2，维度不是 1536**）
- 检索接口 `/api/v1/ai/rag-search`，Top-5 + 相似度评分

### FR-09 通知与审计日志

全系统操作日志存 `audit_logs`，字段含 `user_id / action / resource_type / resource_id / ip_address / created_at`。关键操作（工单创建、作业票签发、LOTO 上锁 / 解锁、AI 调用）强制记录。通知支持站内消息 + WebSocket 推送。

## 3 非功能需求

| 维度 | 指标 |
|------|------|
| 并发 | 支持 200 用户同时在线 |
| 响应 | 页面加载 < 2s，API 响应 < 500ms |
| 可用性 | 单机部署，本地网络依赖 |
| 安全 | JWT 鉴权、Helmet CSP、CORS、CSRF、bcrypt 密码哈希 |
| 数据 | PGlite（开发 / 测试）/ PostgreSQL（生产）双适配，**通过 `DB_TYPE` 环境变量切换** |
| 部署 | Docker Compose 单容器（生产）/ `npm run dev` 本地（开发） |
