# 用户操作手册

> 适用版本：2026-09 校准版 · 配套 §1 FR · §3 DB · §4 部署

## 启动方式

### 方式 A：Docker 单容器（生产 / 演示推荐）

```bash
docker compose up -d
```

浏览器打开 `http://localhost:3000`，系统自动初始化 PGlite 嵌入式数据库并加载演示数据。Godot 3 个游戏（3D 侦探 / 2D 闯关 / 俯视迷宫）在容器构建时已经 copy 进 `public/godot-game*/`。

### 方式 B：本地开发

```bash
npm install
npm run dev
```

Vite 6 + tsx 同进程模式：前端代码改动 HMR 即时刷新，后端代码改动自动重启。PGlite 数据持久化到 `data/.pglite-active.json` 指向的目录。

## 2 工单操作

### 2.1 创建工单（操作工 / 巡检员）

1. 点击左侧导航"工单管理" → 右上角"新建工单"
2. 填写表单：
   - **设备**：下拉选择设备（关联 `equipments` 表）
   - **故障类型**：机械 / 电气 / 仪表 / 管道 / 其他
   - **优先级**：低 / 中 / 高 / 紧急
   - **故障描述**：文本框输入详细描述
   - **来源**（自动）：巡检 / 手动 / AI（来自 `013` 迁移新增 `source` 字段）
3. 点击"提交"按钮
4. 系统检查 15 分钟防重复：
   - 若重复 → 弹出 `409 DUPLICATE_ORDER` 提示，显示已有工单链接
   - 若不重复 → 创建成功，进入 `submitted` 状态

**工单编号格式**：`WO-{YYYYMMDD}-{SEQ}`（SEQ 当日从 001 起）。

### 2.2 接单与派工（车间主任）

1. 进入"待派工"看板列
2. 点击工单卡片进入详情
3. 点击"指派"按钮，选择主修 / 副修
4. 工单状态变更为 `assigned`

### 2.3 执行维修（检修工）

1. 在"我的工单"列表点击"接单"（状态 `assigned → in_progress`）
2. 记录维修过程：
   - 点击"添加评论"填写维修进度
   - 上传维修照片（支持 jpg/png，存 `data/uploads/`）
   - 填写实际工时
3. 维修完成后点击"提交审核"（`in_progress → pending_review`）

### 2.4 审核与关闭（车间主任）

1. 进入"待审核"看板列
2. 查看维修记录和评论
3. 审核通过 → `pending_review → completed`
4. 需返工 → `pending_review → in_progress`
5. 已完成工单自动流转为 `closed`（也可手动 close）

## 3 巡检操作

### 3.1 执行巡检（巡检员）

1. 点击左侧导航"巡检管理"
2. 查看今日巡检任务（日历视图）
3. 点击任务进入巡检表单
4. 逐项检查：
   - 扫描设备二维码签到（WebRTC 摄像头）
   - 勾选检查项（正常 / 异常 / 不适用）
   - 异常项填写备注并拍照
5. 全部完成后点击"提交巡检"

### 3.2 异常项处理

巡检发现异常时，系统自动弹出"创建报修工单"按钮，点击后自动关联设备信息，只需填写故障描述即可快速报修（`source='巡检'`）。

## 4 安全作业票（双人会签）

### 4.1 创建作业票

1. 在工单详情页点击"创建作业票"
2. 选择 6 类之一：动火 / 受限空间 / 高处 / 临时用电 / 吊装 / 盲板抽堵
3. 填写作业内容、安全措施、风险等级（低 / 中 / 高 / 极高）
4. 点击"提交签署"（`status='pending'`）

### 4.2 双人签署

1. 第一签名人（安全员）在"待签署"列表找到作业票
2. 确认安全措施到位后，点击"签署"按钮（`guardian_approval` JSONB 写入）
3. 第二签名人（车间主任）执行相同操作（`supervisor_approval` JSONB 写入）
4. 双签完成后，作业票 `status='signed'`，自动触发关联工单状态流转

### 4.3 LOTO 隔离

1. 作业票签署后，系统提示需要 LOTO 隔离
2. 进入"LOTO 管理"页面
3. 选择锁具编号（如 `LOTO-001`）
4. 点击"上锁"，系统记录上锁时间和操作人（`loto_locks.status='locked'`）
5. 维修完成后，点击"解锁"，需扫码 + 密码双重验证（`status='available'`）

## 5 AI 助手

### 5.1 右下角悬浮 AI 球

页面右下角浮一个 56px 的琥珀色印章式 AI 球（"庖"字 + 蓝青虚线环）。

- **点击**：展开 AI 助手卡片（`340×420`，`headline [人物] · AI 助手`）
- **拖动**：按住挪动位置（Pointer Capture，**跨 iframe 也不卡**——划入 Godot 检修闯关的 iframe 也能继续拖）
- 收起：点 −（最小化）或 ×（关闭）

卡片包含数字人头像区（可拖动卡片头移动整个面板）、消息流、输入框、麦克风（语音输入）、发送按钮。

### 5.2 AI 诊断（24 个能力）

1. 在工单详情页点击"AI 诊断"
2. 系统调用 `POST /api/v1/ai/diagnose`（流式：`POST /api/v1/ai/chat/stream`）
3. 右侧结果区流式显示诊断内容：
   - 故障分类
   - 根因分析
   - 维修方案推荐
   - 置信度评分
4. 底部显示"推荐知识"卡片（来自 `/api/v1/ai/rag-search` Top-5）

### 5.3 知识库检索（RAG）

1. 点击左侧导航"知识库"
2. 搜索框输入关键词（如"反应釜泄漏"）
3. 系统返回相关知识条目（含向量语义匹配）
4. 点击条目查看详细内容
5. 编辑 / 新增条目（archivist 角色）

### 5.4 AI 流水线（多步骤）

`/api/v1/ai/pipeline` 创建多步骤 AI 任务（如"诊断 + 报告 + 推送通知"），SSE 实时显示步骤进展。

### 5.5 AI 降级说明

当 AI 服务不可用时：
- 系统自动降级，显示琥珀色提示条
- 返回 `utils/aiCache.ts` 的 LRU+TTL 缓存结果
- 降级日志记录在 `ai_analysis_log.degraded=true`

## 6 检修闯关（Godot 2D）

### 6.1 进入游戏

1. 点击左侧导航"检修闯关"
2. 系统加载 Godot 4 Web 导出（`/godot-game-2d/index.html`）
3. 首次加载约 3-5 秒（pck + wasm 解压）

### 6.2 操作

- **A / D** 或 ← →：角色左右移动
- **Space / W / ↑**：跳跃
- **E**：与设备互动（走近设备时按 E 触发检修）
- 走到故障设备旁（玫红脉冲环）按 E 弹出检修面板

### 6.3 答题（键盘作答）

- **选工具题**：按数字键 `1`-`4` 选择工具
- **安全判断题**：按 `Y`（正确）/ `N`（错误）
- **排序题**：按数字键依次点击动作（顺序即作答）
- 答完一道会自动跳到下一道

### 6.4 通关

3 道小关全部答完后弹出结算面板：
- 星级（1-3 星，基于正确率）
- 用时
- 正确率
- 关卡名 / 评级（S/A/B/C）

数据 postMessage 回传 React，记录到工单状态。

## 9 常见问题

| 问题 | 解决方案 |
|------|---------|
| 提示 `409 VERSION_CONFLICT` | 页面已过期，点击"刷新"获取最新数据 |
| 提示 `409 DUPLICATE_ORDER` | 15 分钟内已存在相同报修，点击"查看"跳转 |
| AI 诊断无响应 | 检查网络 / 密钥，系统自动降级到缓存或本地规则 |
| Godot 游戏加载慢 | 首次解压 pck + wasm 约 5s，等待 |
| 检修闯关里悬浮球拖不动 | 详见 `docs/说明书重写/3-详细设计说明书.md` §7 —— 必须 Pointer Capture，已修复（`ab27103` / `72a7fd3`）|
| 页面加载慢 | 清除浏览器缓存，或检查 `data/` 目录大小 |
| 无法签署作业票 | 检查是否具有对应角色权限 |
| 登录失败 | 确认演示账号密码正确，注意大小写与 `@2026#` 后缀 |
| 数据库 PGlite 损坏 | `openPgliteWithFallback()` 会自动回退到 `data.bak-*`，详见 `docs/history/修复报告-服务猝死与数据库恢复.md` |
