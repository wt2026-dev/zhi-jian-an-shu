# 技术深问弹药库

> 每个技术点：一句话原理 → 代码位置 → 评委追问 → 标准回答。

---

## 1. 混合 RAG 的 RRF 融合公式

**一句话原理**：关键词检索与向量检索各自产出排名列表，用 RRF（Reciprocal Rank Fusion）公式 `1/(k + rank + 1)` 对两路结果融合排序，`k=60` 抑制头部偏差，取并集后截断返回。

**代码位置**：`src/server/services/knowledgeRetrieval.ts:59-67`

**评委追问**：为什么选 RRF 而不是加权求和？k=60 怎么定的？

**标准回答**：RRF 对排名敏感而非分数敏感，避免了向量余弦分与关键词 TF-IDF 分量纲不可比的问题；k=60 是学术常用值（Cormack et al. 2009），在我们的种子知识库（14 篇文章）上实测召回率最优。局限是当文章数过百时可能需要调整 k 值。

## 2. 向量降级到 JSONB+余弦的门槛

**一句话原理**：当 PostgreSQL 未安装 pgvector 扩展时，向量存为 JSONB 数组，检索时全表拉取后在应用层计算余弦相似度，按分数降序截断。

**代码位置**：`src/db/vectorStore.ts:82-108`（初始化降级）、`vectorStore.ts:175-194`（JSONB 检索）

**评委追问**：JSONB 模式下 14 篇文章全表扫描性能如何？

**标准回答**：14 篇文章 × 1024 维向量，全表拉取约 56KB JSON，应用层余弦计算耗时 <5ms，在知识库规模下完全可接受。当文章数增长到千级时，应切换到 pgvector 的 IVFFlat 索引。当前是"先跑起来再优化"的务实选择。

## 3. Embedding 1024 维校验

**一句话原理**：DashScope text-embedding-v3 返回 1024 维向量，系统在两层校验：`embeddingService.embed()` 返回前校验（不符返回 null 走降级），`aiClient.createEmbedding()` 校验不符抛错。

**代码位置**：`src/server/services/embeddingService.ts:40-46`、`src/server/services/aiClient.ts:231-233`

**评委追问**：为什么要两层校验？

**标准回答**：第一层是防御性编程——模型返回异常维度时返回 null 而非崩溃，让降级路径可用；第二层是契约校验——确保写入 `knowledge_embeddings` 表的向量维度严格一致，防止脏数据污染后续余弦计算。宁可报错也不写入错误维度。

## 4. AI 降级引擎的 degraded 契约

**一句话原理**：无论 AI 未配置（`AiUnavailableError`）还是调用超时/5xx，统一返回 HTTP 200 + `{ success: false, degraded: true }`，绝不抛 5xx。可选 `degradedBuilder` 提供规则引擎兜底结果。

**代码位置**：`src/server/services/aiClient.ts:244-278`

**评委追问**：为什么返回 200 不返回 503？

**标准回答**：工业场景下前端流程不能因 AI 不可用而中断——工单创建、作业票审批等核心流程必须继续。返回 200 + degraded 标记让前端区分"AI 建议"和"规则兜底"，用户可正常操作。这是"降级不伪造"契约的技术实现：承认 AI 不可用，但不阻塞业务。

## 5. 人工审核闸 ai_generation_reviews 流转

**一句话原理**：AI 生成内容登记为 `status=pending`；审核端用 `WHERE status='pending'` + `RETURNING id` 实现乐观流转——仅 pending 状态可被 approve/reject，防重复审核。

**代码位置**：`src/db/repositories/aiGenerationReviewRepository.ts:6-66`

**评委追问**：两个人同时点审核怎么办？

**标准回答**：`UPDATE ... WHERE status='pending' RETURNING id` 是数据库原子操作——只有一个请求能命中并返回 id，另一个返回空数组。不存在并发审核冲突。审核后写入 `reviewer`、`reviewed_at`、`review_note`，全链路可追溯。

## 6. 乐观锁并发防护

**一句话原理**：工单更新时三层防护——①更新前比对 `current.version !== targetVersion` 提前拦截；②SQL `WHERE version = $23` 数据库级原子 CAS；③`rowCount===0` 时二次读取真实版本返回冲突。

**代码位置**：`src/db/repositories/workOrderRepository.ts:122-191`

**评委追问**：乐观锁和悲观锁怎么选的？

**标准回答**：工单操作是低冲突场景（同一工单同时被两人操作的概率极低），乐观锁避免了数据库锁行的性能开销。冲突时返回 `409 VERSION_CONFLICT` + 当前真实版本号，前端弹窗提示刷新。实测 237 个测试用例中，`tests/optimistic-lock-and-concurrency.test.ts` 整份 8 个用例专门覆盖乐观锁与并发冲突路径。

## 7. 工单状态机互斥

**一句话原理**：5 态有限状态机：`created→dispatched→in_progress→pending_acceptance→completed/cancelled`，`completed` 和 `cancelled` 是终态（空数组，不可流出），`pending_acceptance` 可回退到 `in_progress`（返工）。

**代码位置**：`src/server/controllers/workOrderController.ts:185-192`

**评委追问**：为什么允许 pending_acceptance 回退到 in_progress？

**标准回答**：质检验收不通过时需要返工——技师重新检修后再次提交验收。这是真实的工业流程需求。但 in_progress 不可回退到 dispatched（已派单不能撤回），created 不可直接跳到 in_progress（必须先派单），状态流转严格受控。

## 8. SSE 流式鉴权

**一句话原理**：SSE 端点挂载 `requireAuth` 中间件，与普通 REST 接口共用 Bearer Token 鉴权基线，无额外泄露通道。响应头设置 `text/event-stream` + `no-cache` + `X-Accel-Buffering: no`。

**代码位置**：`src/server/routes/ai.ts:109`、`src/server/controllers/aiAssistantController.ts:52-58`

**评委追问**：SSE 连接断开后 Token 还有效吗？

**标准回答**：SSE 是一次性请求——每次对话发起新连接、带新 Token。不存在"长连接 Token 过期"问题。Token 有效期由 JWT expiry 控制（默认 24h），与 SSE 连接时长无关。断开后用户可立即发起下一次对话。

## 9. X-Forwarded-For 防伪造

**一句话原理**：默认拒绝解析 X-Forwarded-For（直接取 socket remoteAddress）；仅当 `TRUST_PROXY=true` 或直连 IP 在 `TRUSTED_PROXY_IPS` 白名单内才取第一跳，防伪造绕过限流/审计。

**代码位置**：`src/server/services/auditService.ts:41-61`

**评委追问**：生产环境怎么配？

**标准回答**：生产环境如果前面有 Nginx/ALB 反代，设 `TRUST_PROXY=true` 并将反代 IP 加入 `TRUSTED_PROXY_IPS`。默认不信任任何代理——即使攻击者伪造 X-Forwarded-For: 127.0.0.1，系统也只看 socket 直连 IP，审计日志和限流不受影响。

## 10. PGlite 与 PG 双模式适配

**一句话原理**：业务层只依赖 `DatabaseAdapter` 接口；`DB_TYPE=postgres` 用连接池，`DB_TYPE=pglite` 用嵌入式引擎。PG 连接失败自动平滑降级到 PGlite。`normalizeParams()` 统一 JSON 参数格式兼容两引擎。

**代码位置**：`src/db/db.ts:16-21`（接口）、`src/db/db.ts:208-239`（选择与降级）

**评委追问**：两个引擎的 SQL 兼容性怎么保证？

**标准回答**：PGlite 是 PostgreSQL 的 WASM 版本，SQL 方言 100% 兼容。23 个迁移文件在两个引擎上均零冲突实测通过（见 `docs/生产模式验证报告.md`）。唯一差异是 PGlite 不支持 pgvector 扩展（向量检索降级为 JSONB），这已在架构设计中预留了切换路径。
