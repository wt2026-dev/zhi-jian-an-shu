## 二、差距清单（逐项：现状证据 → 风险 → 措施 → 待确认）

### G1. 工单工作流全链路无角色校验【高危，阶段 2 优先】
- **证据**：`routes/workorders.ts` 全部只挂 `requireAuth`；`controllers/workOrderWorkflowController.ts`（560 行）0 处 role/403；服务层无兜底。即任何已认证账号（含 operator）可派单、开工、完工、**验收**。
- **风险**：违反"验收必须由明确授权的人执行"的试点红线；审计记录无法区分越权操作。
- **措施**：为 dispatch/accept/archive 等高危端点按业务口径补 `requireRole`，服务端重校验操作者身份；补越权测试（未认证/越权/并发）。
- **待确认**：派单/验收/归档各自允许哪些角色（建议：派单=manager/admin，验收=manager/admin，开工/完工=technician/inspector 本人）。

### G2. 生产环境自动灌入演示账号与演示业务数据【高危，阶段 1】
- **证据**：`db.ts:396-404` users 表为空即自动 `seedDatabase()`，写入 9 个**源码固定口令**的演示账号（`seed.ts:44-48`）+ 演示设备/工单/遥测数据。
- **风险**：试点现场首次启动即带 9 个已知口令的账号和假业务数据；与"不伪造现场数据"冲突。
- **措施**：新增 `SEED_MODE=demo|minimal|off`（默认 demo 保持现状兼容；试点文档要求 `minimal` 仅建 admin 或 `off` + 管理端建号）；演示口令仅在 demo 模式写入。
- **待确认**：试点环境初始管理员账号如何建立（环境变量注入初始口令？首启强制改密？）。

### G3. 迁移无版本追踪，靠"already exists"吞错【中危，阶段 1】
- **证据**：`db.ts:348-387` 每次启动全量重跑 27 个 .sql，逐语句执行，报错文案含 "already exists"/"duplicate" 即吞掉。
- **风险**：非幂等语句的意外报错被静默吞掉；真 PG 上文案匹配脆弱；无法知道当前 schema 版本；回滚无依据。
- **措施**：引入 `schema_migrations` 版本表（已应用则跳过），迁移失败 fail-fast 且不启动服务；补"迁移失败→启动失败"的测试。
- **待确认**：无。属低风险内部改造（首启自动建版本表并记录现状）。

### G4. 备份为活数据目录直接 tar【高危，阶段 3】
- **证据**：`scripts/backup.sh` 对 `DATA_DIR` 直接 `tar -czf`（运行中 PGlite 目录，非一致性快照）；`restore.sh` `rm -rf /data/*` 后解包。
- **风险**：备份期间数据写入 → tar 内文件版本不一致，恢复可能损坏（PGlite 已知强杀即坏目录）；无备份失败告警、无加密、无校验。
- **措施**：备份前停写（或用 PG 自带 `pg_dump` 通道当 DB_TYPE=postgres）；补备份后校验（解包试开 + 表计数）；失败退出码 + 告警钩子；恢复脚本加二次确认与目标目录校验；新增隔离环境恢复演练脚本。
- **待确认**：备份频率/保留期/目标位置（异地？）、是否需要备份加密、RTO/RPO 目标值。

### G5. 限流/登录锁/JWT 撤销表均为进程内【取决于部署形态】
- **证据**：`rateLimit.ts:31,153`、`authService.ts:12` 均为进程内 Map/Set；`rateLimit.ts:5-26` 注释已如实声明单实例约束与 Redis 升级路径。
- **风险**：仅当多副本部署时构成差距；单机部署下成立。
- **措施**：若确认单机部署 → 保持现状并在部署文档写明"禁止 --scale"约束；若多副本 → 抽象存储接口 + Redis 实现（需新增 Redis 依赖）。
- **待确认**：**部署形态（厂内单机 docker compose？多副本？）——这决定阶段 2 是否引入 Redis**。

### G6. 日志与可观测性细节【中危，阶段 3】
- **证据**：`requestLogger.ts` 无敏感字段脱敏逻辑（仅 import jwt）；结构化日志模块存在（`utils/logger.ts`）。
- **风险**：请求日志可能落 Authorization 头/口令字段；排障时泄露凭据。
- **措施**：logger 增加敏感字段 redact（password/token/secret/authorization）；补脱敏单测；把 DB 连通性/迁移版本纳入 `/ready` 明细。
- **待确认**：日志留存周期、日志落盘位置与轮转策略。

### G7. 演示附件与正式业务混排【低危，阶段 5】
- **证据**：导航含 Godot 迷宫（`/godot-maze`）、数字人、拆解视图等演示入口；CSP 白名单含第三方数字人/地图域名。
- **风险**：试点用户误入演示功能；外网 CDN 依赖在内网不可达（数字人/高德/AI 均为云服务）。
- **措施**：试点构建导航开关（环境变量控制演示入口显隐），不删资产；文档写明内网运行时的外部依赖降级行为（AI 已有 degraded 标记）。
- **待确认**：试点现场是否有外网出口；哪些演示功能试点期间保留。

### G8. 数字孪生大文件（阶段 4，另行进行中）

## 三、不能擅自假设、需要用户/现场确认的参数

| 参数 | 为什么不能猜 | 保守默认（阶段 1-3 代码先行采用，可配） |
|------|--------------|------------------------------------------|
| 部署形态（单机/多副本） | 决定限流/锁/撤销表是否必须共享存储 | 按**单机单实例**实施，文档写明约束 |
| 预计并发（在线用户数） | 影响限流阈值与连接池参数 | 连接池 10、全局限流 600/min 维持 |
| RTO/RPO | 决定备份频率与是否需要热备 | 不宣称；备份每日 1 次起步，可配 |
| 离线运行要求 | AI/地图/数字人均为云依赖 | 按**有外网、AI 可降级**实施，文档写明 |
| 日志留存周期 | 存储与合规要求 | 本地 30 天轮转（可配，未宣称合规） |
| 备份目标位置 | 异地/本机第二块盘/外挂存储 | 本机 `BACKUP_DIR` 可配，支持指向挂载盘 |
| 初始账号建立方式 | 生产不能复用演示口令 | `SEED_MODE` 三档，试点用 minimal/off |
