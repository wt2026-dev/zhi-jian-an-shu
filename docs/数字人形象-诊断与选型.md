# 数字人形象诊断与选型

> 日期：2026-09-17
> 背景：反馈「数字人是动漫形象，要改成符合工程师/工业项目风格」
> 结论先行：**当前画面上的动漫形象不是设计选择，而是云渲染服务不可用后的本地降级替身。**

---

## 一、根因：魔珐星云积分不足，从未成功加载过

用 `.env` 中的真实凭证复刻 `wechatController.handleXingyunSession` 的签名逻辑，直连网关实测：

```
POST https://nebula-agent.xingyun3d.com/user/v1/ttsa/session
HTTP 200 | 263 ms
error_code: 5
error_reason: "您的积分不足, 请及时充值"
```

**凭据本身是有效的**（签名校验通过、返回了业务错误码而非鉴权失败），**失败原因是账户积分耗尽**。

因此调用链实际走向是：

```
DigitalHumanAvatar
  └─ 请求 /api/v1/xingyun/session
       └─ 星云网关返回 error_code 5「积分不足」
            └─ setSdkStatus('error') → 降级
                 └─ 渲染本地 DigitalHuman3D（程序化工程师）  ← 你看到的
```

也就是说：**项目里集成了写实数字人，但一次都没真正跑起来过。**

### 附带发现：这个失败是完全静默的

`fallbackReason` 只被 `updateFallbackReason()` 赋值，**没有任何 JSX 渲染它**，仅存在于 `console.warn`。
用户侧看到的是「自研3D数字人・本地渲染」，与正常运行无异 —— 无从得知积分已耗尽。

**已修复**：`sdkStatus === 'error'` 时在头像区顶部渲染琥珀色提示条，显示真实原因；
当原因包含「积分/余额/充值」时追加「（请到魔珐星云控制台充值后重试）」。

## 二、为什么本地替身看起来是动漫的

`EngineerModel.ts` 原本是一套标准二次元渲染管线，与「戴了安全帽」无关：

| 动漫特征 | 代码证据 |
|---|---|
| 卡通赛璐璐着色 | `toonMat()` → `MeshToonMaterial` + 3 级 `gradientMap`（共 23 处） |
| 黑色描边 | `addOutline()` → 反向外壳 `BackSide` + 黑色 |
| Q 版大头比例 | 头宽 0.96 vs 肩宽 1.14 → 头肩比 **0.84**（真实成人约 0.36–0.45） |
| 动漫眼三件套 | 眼白 0.072 + 瞳孔 0.04（占 55%）+ 白色高光小球 0.015 |

**已修复**：材质全量改为 PBR（`MeshStandardMaterial`，安全帽按光滑工程塑料、工具按金属调参）；
描边移除；头部整体缩放至头肩比 **0.571**；眼睛改为「眼白 + 虹膜 + 瞳孔」真眼层次（瞳孔占比 0.50，真人约 0.46）。

实测（`scratch/measure-engineer.ts`）前后对比：

| 指标 | 改前 | 改后 |
|---|---|---|
| 头肩比 | 0.84（Q 版） | **0.571** |
| 卡通材质 / 描边 | 23 / 有 | **0 / 0**（50 个 PBR） |
| 瞳孔占眼球 | 0.55（无虹膜层） | **0.50** |
| 头底 vs 脖子顶 | — | 0.840 < 0.860（相接无浮空） |

## 三、为什么「换个开源 VRM」解决不了

按建议去 VRM 生态找现成模型，结论是**这条路走不通**，有实测证据：

1. **生态几乎全是动漫向。** 日方「法人提供 VRM」清单（orecen）按 50 音顺罗列的免费模型
   —— アリシア・ソリッド、キズナアイ、プロ生ちゃん、つくよみちゃん、東北ずん子、ミライ小町……
   **全部是动漫/VTuber 角色**。唯一的写实例外是「VJ TAKAGI」（日本搞笑艺人的真人扫描），
   既不是工程师，也不适合本项目。

2. **动漫感烧在材质里，换模型去不掉。** 解析实际文件：

   | 模型 | specVersion | 材质 |
   |---|---|---|
   | 现有 AvatarSample_A/B/C | **0.0** | `KHR_materials_unlit`（平面卡通着色） |
   | 实测下载的 Alicia Solid（公认写实向） | **0.0** | **12/12 全部 `KHR_materials_unlit`** |

   `KHR_materials_unlit` 是无光照平面材质 —— 不管模型画得多写实，渲染出来都是平片。
   要救必须加载后程序化把 unlit 转 PBR，等于还是我们自己动手。

3. **规范版本也不匹配。** `@pixiv/three-vrm@3.5.5` 的
   `POSSIBLE_SPEC_VERSIONS = Set(["1.0","1.0-beta"])`，主路径只认 VRM 1.0；
   而这些免费模型全是 0.x，需 `acceptV0Meta` + V0 兼容层 —— 现有 `DigitalHumanVRM.tsx`
   **只写了 `VRMUtils.rotateVRM0(vrm)`，没设 `acceptV0Meta`**，且该文件当前是死代码（无人引用）。

4. **工装/工程师向的免费 VRM 基本不存在。** VRoid Hub 上「作業着・ヘルメット」只是
   **服装素材**（需登录、受平台条款限制），不是可直接下载使用的完整模型。

> 补充：实测沙箱可下载 GitHub 文件（Alicia Solid 下到 7,534,400 字节），
> 所以「下不到」不是障碍 —— 障碍是**没有合适的模型**。

## 四、三条路

| 方案 | 效果 | 代价 | 说明 |
|---|---|---|---|
| **A. 给魔珐星云充值**（推荐） | **写实数字人**，与参考视频同一档次 | 需付费 | 代码已集成完毕，充值即恢复，零开发量 |
| B. 本地换写实模型 | 取决于找不找得到 | 高，且外观我无法验证 | 需非 VRM 的写实绑定 GLB；我看不了图，必须你目测确认 |
| C. 继续优化程序化工程师 | 已去动漫化，但仍是"手搓"观感 | 低 | 本轮已做，可作为永久兜底 |

**推荐 A**：这是唯一能达到参考视频观感的方案，且不需要任何代码改动。
本地替身（C）无论怎么调都追不上云端的写实渲染，但它应当保留为**离线/无积分时的兜底** ——
本轮的去动漫化改造正是为了让兜底不至于掉档太狠。

### 关于形象选择

星云的**具体形象在魔珐星云控制台绑定到 APP_ID**，代码侧 session 只传
`tag` / `gateway_type` / `config`，**无法指定用哪个形象**。
所以充值后显示的是后台当前配置的形象 —— 若想换成工程师/工装形象，需要在星云控制台更换。
