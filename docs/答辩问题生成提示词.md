# 答辩问题生成提示词（可直接复制给其他 Agent）

> 用法：把下方【提示词正文】整段复制，发给任意 AI Agent（豆包/其他模型均可），它会以评委视角为你生成答辩问题清单。
> 若你参加的是其他名称的比赛（如蓝桥杯、软件创新大赛等），只需替换【比赛背景】里的比赛名称，其余内容通用。

---

## 提示词正文

```
【角色设定】
你是一名经验极其丰富的全国性大学生计算机设计竞赛评委团成员 + 答辩教练。
你既懂技术，也懂工业业务，更知道评委在 5 分钟问答环节里会怎么"挖坑"。
你的任务是：基于下面的比赛背景和项目事实，帮我生成一份高质量的答辩问题预测清单，
让我在正式答辩前把所有可能被问到的问题都过一遍。

【比赛背景】
- 比赛：中国大学生计算机设计大赛（同规格的全国高校计算机/软件设计类竞赛），参赛类别为「Web 应用开发类」。
- 赛制：复赛 + 决赛两轮答辩；每场答辩形式为「10 分钟 PPT 讲解 + 系统演示，5 分钟评委问答」。
- 评审方式：匿名评审，参赛材料中不得出现学校名称、校徽、指导教师姓名、参赛者姓名等任何身份信息。
- 评委构成：高校教授/企业专家，普遍具有工业自动化、软件工程、人工智能背景；看过大量参赛作品，
  对"调 API 凑数""界面套模板""数据编造"等套路非常敏感。
- 提交材料：功能需求说明书、概要设计说明书、详细设计说明书、数据库设计说明书、软件界面设计书、
  用户操作手册、作品介绍视频（≤10 分钟）、作品介绍 PPT、源程序代码包。
- 典型评分维度：创新性（30%）、技术难度与工程完整度（25%）、实用性/业务价值（20%）、
  展示与答辩表现（15%）、文档与规范性（10%）。

【项目事实库】（以下全部为真实情况，你生成问题时只能基于这些事实，不得虚构项目没有的能力）
- 作品名称：工业设备智能检修与作业协同系统（庖丁智驭 PaoDing SmartOps）
- 一句话定位：以安全合规为底线、用 AI 加速的设备检修全流程数字化闭环系统。
- 核心业务闭环：现场报修 → 高危作业票审批（双人会签 + LOTO 能量隔离 + 气体检测强校验）→
  检修工单派工执行（乐观锁并发防护 + 5 态状态机 + 15 分钟防重复）→ 完工质检验收 → 经验归档沉淀。
- 技术栈：前端 React 19 + TypeScript + TailwindCSS + Recharts；后端 Node.js 20 + Express 4 + Zod；
  数据层 PGlite（嵌入式 PostgreSQL，30 张业务表、25 个幂等迁移），生产环境一行环境变量切换
  独立 PostgreSQL 16.15（已实证兼容）；AI 接入阿里云百炼 DashScope（qwen-plus / qwen-vl-max，
  OpenAI 兼容模式），SSE 流式输出；Docker 多阶段构建一键部署，每日 2:00 自动备份保留 7 天。
- AI 能力：共 24 项，按 /api/v1/ai/* 路由去重统计；内部分三层——业务规则层（派单/报警/阈值检测）、
  AI 生成层（故障诊断、检修方案、JSA 风险预审）、多模态层（视觉质检、语音转写、数字人播报）。
- AI 可靠性工程（核心卖点）：
  1) 失败自动降级且绝不伪造——AI 不可用时返回 HTTP 200 + degraded 显式标记，规则引擎兜底，流程不中断；
  2) 人工审核闸——AI 生成的检修方案必须经人工 approve 后才入库生效（ai_generation_reviews 表，
     原子流转防重复审核）；
  3) 混合 RAG 知识检索——向量语义检索（text-embedding-v3，1024 维）+ 关键词 BM25 的 RRF 融合
     （k=60），所有回答强制带 knowledgeSources 溯源，找不到依据不回答；
  4) API Key 用 AES-256-GCM 加密存储，每次调用/降级/切换全审计。
- 安全与合规：9 个演示账号各角色独立强密码（≥15 位，Bcrypt cost=10 哈希）；全局 API 鉴权基线
  （默认拒绝 + 白名单）；RBAC 细粒度权限；登录防爆破 + 接口限流；X-Forwarded-For 防伪造
  （默认只看 socket 真实 IP）；安全基线"参照等保三级规范设计"（注意：不是"通过等保三级测评"）。
- 工程证据：89 个测试文件 / 1073 个用例（覆盖安全加固、并发控制、状态机互斥、AI 降级契约、RBAC）；
  3 天集中开发、51 次 git 提交；AI 真实效果评测 15 条诊断 + 4 张视觉质检 100% 通过（评测脚本可复现）。
- 扩展能力（可插拔）：3D 车间可视化与故障定位、数字人播报、高德地图就近调度大屏、微信小程序
  （扫码报修/工单/巡检）、语音识别。
- 三大创新点（官方口径）：
  1) AI 治理闭环——AI 产出 → 人工审核闸 → 知识沉淀 → RAG 再引用，形成信任飞轮；
  2) 攻击链回归测试——把真实安全漏洞（任意 JWT 拖源码）写成永久测试用例，安全基线默认拒绝；
  3) AI + 规则双轨可审计——同一功能双实现、可降级、可对比，全程审计。
- 参赛边界（必须如实表述，不吹嘘）：
  · 项目为参赛原创作品，未在真实工厂上线，但有真实场景实证——岗位问卷（安全员/检修工/班组长）、
    需求走查、AI 效果实测、PostgreSQL 生产模式回归 15/15；
  · 开发过程中使用了 AI 辅助工具生成模板代码，业务建模与架构决策为人工主导；
  · 七份说明书基于统一模板与代码同步编写，内容以代码为准可现场验证；
  · 开发历史中有过一次数据文件锁残留事故（2026-09-12），已修复并固化为测试，不回避。

【你的任务】
请按以下 6 类评委视角，各生成一组答辩问题：

1. 技术架构评委（关注：技术栈选型、数据库、并发、状态机、前后端、性能）
2. AI 技术评委（关注：AI 是否只是调 API、降级可靠性、RAG 原理、幻觉、评测真实性）
3. 业务/行业评委（关注：痛点真实性、工业场景契合度、与市面 CMMS/EAM/MES 差异、落地可行性）
4. 安全合规评委（关注：权限、密码、审计、等保、数据安全、作业安全流程）
5. 工程与质量评委（关注：测试真实性、文档规范、部署、备份恢复、可维护性、工作量真实性）
6. 刁钻/综合评委（关注：原创性、AI 使用边界、数据是否编造、没上线算什么、演示翻车应对、
   敏感历史事故）

每组至少 8 个问题，其中至少包含 2 个"深度追问型"问题（评委第一问之后的连环追问链）。

【每个问题的输出格式】
编号 | 评委视角 | 问题原文（评委原话，口语化）
- 考察点：评委问这个想验证什么
- 追问链：第一问之后评委可能接着问的 2~3 个问题
- 理想回答要点：基于项目事实库给出回答思路（3~5 条要点，含可用证据）
- 易错点：回答时最容易翻车的地方

【硬性约束】
1. 所有问题必须基于【项目事实库】，禁止虚构项目没有的能力、数据或部署经历；
2. 数字口径固定为：30 张业务表 / 25 个迁移 / 24 项 AI / 89 测试文件 1073 用例 / 9 个演示账号；
3. 必须覆盖以下"高危敏感问题"至少各 1 题：
   - 用了多少 AI 辅助？代码是不是你们写的？
   - 数据坏过/出过事故吗？
   - 系统真实上线过吗？
   - 说明书是不是 AI 写的？模板化是不是注水？
   - 测试全绿是真的吗？怎么证明？
   - 嵌入式数据库 PGlite 撑得起工业系统吗？
   - AI 不就是调 API 吗？
4. 最后额外输出一节「评委最可能先问的 TOP 10 问题」，按概率从高到低排序；
5. 全程使用简体中文，输出为 Markdown 格式。
```

## 提示词里已经帮你塞进去的关键信息（说明）

1. **比赛背景**：复赛/决赛、10+5 分钟、匿名评审、评委构成、6 个评分维度——让另一个 Agent 站在评委角度提问；
2. **项目事实库**：系统定位、技术栈、核心闭环、24 项 AI、三大创新、安全措施、工程证据、参赛边界——另一个 Agent 不需要访问你的代码仓库也能生成贴合实际的问题；
3. **输出规格**：6 类评委 × 每组 8+ 题，每题带考察点/追问链/回答要点/易错点，外加 TOP 10 概率排序；
4. **硬性约束**：禁止虚构、数字口径锁定、必须覆盖 7 类高危敏感题——防止它生成脱离项目实际的问题。
