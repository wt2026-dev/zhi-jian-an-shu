### 攻击路径闭合证明
1. **统一环境变量键名**：修复前由于键名不匹配导致微信调用永走降级分支；修复后键名与配置完全对齐。
2. **生产环境绝对封禁**：在生产模式（`NODE_ENV=production`）下，任何未配置微信官方凭据的请求均直接被 503 截断，无法进入派生或绑定分支。
3. **消除越权通道**：即使在本地开发调试模式下，未配置 `WX_DEFAULT_USERNAME` 直接返回 401；若配置为 `admin` 或 `manager`，直接被策略拦截返回 401（错误码 `WX_DEV_FORBIDDEN_ROLE`），攻击者绝无法再通过小程序登录端点获取系统管理员权限。

## 五、遗留风险与说明

1. **多节点部署环境下的缓存同步**：
   - 当前系统的 `reloadUsers()` 刷新的是单实例进程内部的 `dbUsers` 内存引用。单体部署或单容器模式下完全即时生效；若未来系统向多节点水平扩展（集群部署），建议将用户状态变更发布到 Redis Pub/Sub 或 PostgreSQL LISTEN/NOTIFY，通知各节点同步刷新用户内存缓存。
2. **生产环境真实微信凭证配置建议**：
   - 上线生产部署前，必须在 `.env` 中正确填入真实已认证的 `WECHAT_APP_ID` 与 `WECHAT_APP_SECRET`，并确保外网可正常连通微信 API 服务器；切勿在生产环境设置 `WX_DEFAULT_USERNAME`。
3. **演示密码安全加固与强制改密策略**：
   - 种子数据与开发演示账号已全面升级为各角色独立强密码（Bcrypt 哈希存储，如 `Admin@2026#Demo`、`Manager@2026#Safe` 等），彻底消除了“全角色同密码”安全弱点。
   - 登录模块已支持 `DEMO_FORCE_PASSWORD_CHANGE=true` 环境变量开关，启用时登录成功将返回 `forcePasswordChange: true` 并在前端弹出引导修改初始密码，满足等保三级基线要求。
