# 运营指标基线

> 生成时间：2026-09-14 | 数据来源：全部从已有表聚合，不新建表

## 指标体系概览

| 类别 | 指标 | 数据来源表 | 用途 |
|------|------|-----------|------|
| A. AI 采纳率 | adoption_rate_pct | ai_analysis_log, work_orders, ai_knowledge_contributions | 衡量 AI 工具实际使用率 |
| B. 工单效率 | P50/P90 各阶段耗时 | work_orders | 衡量维修响应与执行效率 |
| C. 安全合规 | 字段完整率/逾期率/双人会签率 | safety_permits | 衡量安全作业票合规性 |
| D. AI 质量 | 好评率/降级率 | ai_feedback, ai_generation_reviews | 衡量 AI 输出质量 |
| E. 系统可靠性 | 错误率/拦截率 | audit_logs | 衡量系统稳定性与安全性 |

---

## A. AI 采纳率

**定义**：AI 分析后 7 天内产生工单或知识贡献的比例

**计算逻辑**：
- 分母：`ai_analysis_log` 总行数（AI 被调用的总次数）
- 分子：`ai_analysis_log` 中，后续 7 天内 `work_orders` 或 `ai_knowledge_contributions` 有新增的记录数
- 公式：`(ai_with_work_order + total_contributions) / total_ai_calls × 100%`

**基线值**（种子数据）：
| 指标 | 值 |
|------|-----|
| AI 分析总次数 | 10 |
| 后续产生工单数 | 10 |
| 知识贡献数 | 14 |
| **AI 采纳率** | **240%**（贡献数 > 调用数，说明知识复用率高） |

**解读**：采纳率 >100% 表示一次 AI 分析产生了多个下游成果（工单+知识贡献），属正常现象。

---

## B. 工单效率

**定义**：工单全生命周期各阶段耗时（P50 中位数 / P90 九十分位数）

**计算逻辑**：
- 创建→派发：`dispatched_at - created_at`
- 派发→完成：`completed_at - dispatched_at`
- 完成→验收：`accepted_by_inspector_at - completed_at`
- 仅统计状态完整的工单（已验收），排除进行中工单

**基线值**（种子数据）：
| 阶段 | P50 | P90 | 样本数 |
|------|-----|-----|--------|
| 创建→派发 | — | — | 0（种子数据无 dispatched_at） |
| 派发→完成 | — | — | 0 |
| 完成→验收 | — | — | 0 |

**说明**：种子数据的工单未设置 `dispatched_at` / `completed_at` 等时间戳，因此基线值为空。生产环境运行后会产生真实数据。

---

## C. 安全合规

**定义**：安全作业票的规范性与执行率

**计算逻辑**：
- **字段完整率**：`precautions` + `hazards` + `safety_checklist` 均为非空数组的作业票占比
- **逾期率**：已过 `valid_until` 但未 `closed_at` 的作业票占比
- **双人会签率**：`guardian_approval.signed = true` 且 `supervisorApproval.signed = true` 的占比

**基线值**（种子数据）：
| 指标 | 值 |
|------|-----|
| 作业票总数 | 10 |
| 字段完整数 | 10 |
| 逾期数 | 0 |
| 双人会签数 | 10 |
| **字段完整率** | **100%** |
| **逾期率** | **0%** |
| **双人会签率** | **100%** |

**说明**：种子数据为理想状态，生产环境会有波动。

---

## D. AI 质量

**定义**：AI 输出的人工评审质量

**计算逻辑**：
- **好评率（approval_rate）**：`ai_feedback` 中 `status = 'adopted'` 的占比
- **降级率（rejection_rate）**：`ai_generation_reviews` 中 `status = 'rejected'` 的占比

**基线值**（种子数据）：
| 指标 | 值 |
|------|-----|
| 反馈总数 | 8 |
| 采纳数 | 5 |
| 评审总数 | 10 |
| 拒绝数 | 3 |
| **好评率** | **62.5%** |
| **降级率** | **30%** |

**解读**：
- 好评率 >60% 为健康水平
- 降级率 <20% 为理想水平，当前 30% 偏高，需关注 AI 输出质量

---

## E. 系统可靠性

**定义**：API 层面的错误与拦截统计

**计算逻辑**：
- **错误率**：`audit_logs` 中 `status = 'FAILED'` 的占比
- **拦截率**：`audit_logs` 中 `status = 'BLOCKED'` 的占比
- **限流命中**：`action_type` 包含 `RATE_LIMIT` 或等于 `RBAC_ACCESS_DENIED` 的记录数

**基线值**（种子数据）：
| 指标 | 值 |
|------|-----|
| 审计日志总数 | 30 |
| 失败数 | 0 |
| 拦截数 | 3 |
| 限流命中 | 0 |
| **错误率** | **0%** |
| **拦截率** | **10%** |

**解读**：
- 错误率 <1% 为健康水平
- 拦截率 10% 表示 RBAC 权限控制正常工作（非 admin 用户尝试访问受限资源）

## 访问方式

### API 端点（推荐）
```
GET /api/v1/admin/metrics/operational
Authorization: Bearer <admin_token>
```

返回 JSON 格式，包含全部 5 类指标。

### 脚本方式
```bash
npx tsx scripts/metrics-report.ts --markdown  # Markdown 格式
npx tsx scripts/metrics-report.ts --json      # JSON 格式
```

> **注意**：脚本在 PGlite 嵌入式模式下可能因 WASM 内存问题崩溃。如遇此问题，请使用 API 端点。
