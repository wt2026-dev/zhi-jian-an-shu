## 1. 改造前的真实基线（重新实测，不引用记忆值）

沿用 Phase-1 的做法：把改动前的生产包 `dist.prev-200141/` 用零依赖静态服务器
`scratch/baseline-run/serve-static.mjs` 伺服在 `:3100`，并把 `/api`、`/uploads` 反代到当前后端 `:3000`。
于是得到 **旧前端 + 当前后端 + 同一数据库 + 同一台机器**，测出来的就是纯粹的"改造前"。

> 反代需把 `Origin`/`Referer` 改写成后端 CSRF 白名单里的 `http://127.0.0.1:3000`，
> 否则会被 403 挡下。CSRF 校验逻辑一字未改，请求仍须带正确账号密码。

### 1.1 定位到的五个真实病灶（都是查出来的，不是猜的）

| # | 病灶 | 证据 |
|---|---|---|
| 1 | **页面外壳把背板盖死** | `App.tsx` 的 shell 与 `<main>` 都刷了不透明 `bg-[#f8fafc]`，把 `body` 上的渐变背板整层盖住 —— 这才是"像一张死白纸"的**真正原因**（`CockpitDashboardView.tsx` 也有一处同样写法） |
| 2 | **全局 `!important` 把光影压平** | 旧 CSS 的 `[class*=shadow-*]` 一律替换成扁平阴影、`[class*=rounded-*]` 一律压到 14px、`[class*=animate-ping]{animation:none}` —— 层次与呼吸感被系统性抹掉 |
| 3 | **`<body>` 被兼容层刷白** | `index.html` 里写的是 `<body class="bg-slate-900 …">`，命中旧 CSS 的 `[class*=bg-slate-900]{background-color:#fff!important}`，把 body 刷成纯白、压掉背板底色 |
| 4 | **近黑遮罩是"死黑压抑"的来源** | 旧 CSS **没有** `[class*=bg-black]` 兜底，所以 `bg-black/80`、`bg-black/75` 这类遮罩**在旧版就是真·近黑**（实测合成白底后 `rgb(51,51,51)`，感知亮度 51） |
| 5 | **两个关键动画从未生效** | `digital-human-breath` 与 `.avatar-eyes` 在 `src/` 和旧产物包里**都查不到定义**，只有引用 —— 2D 数字人的呼吸与眨眼一直是死的（潜伏 bug） |

> 第 3、5 条是本次重构**顺带挖出来的既有缺陷**，不是本轮引入的。

### 2.2 全屏遮罩：感知亮度（这是"死黑压抑"的量化消解）

判定方法：把遮罩色**合成到白底**后用 sRGB 相对亮度公式算感知亮度 —— 遮罩盖在明亮页面上，用户看到的就是这个合成结果。

| 取证目标 | 改造前 | 改造后 |
|---|---|---|
| **`bg-black/80`**（工单详情抽屉） | `oklab(0 0 0 / 0.8)` + `blur(8px)`<br>合成白底 `rgb(51,51,51)` → **亮度 51，近黑 = true** | `rgba(230,239,250,0.62)` + `blur(10px) saturate(1.4)`<br>合成白底 `rgb(240,245,252)` → **亮度 244，近黑 = false** |
| **`bg-slate-900/40`**（驾驶舱 KPI 下钻抽屉） | `rgb(255,255,255)` + `blur(8px)` → 亮度 255<br>（旧 CSS 已有 `[class*=bg-slate-900]{background:#fff!important}`，**这些遮罩在旧版就已被兜底成纯白**） | `rgba(230,239,250,0.62)` + `blur(10px) saturate(1.4)` → 亮度 244 |

> **诚实说明**：`bg-slate-900/40` 这一条**改造前后都是亮的**，不具区分度（旧版被兜底成纯白，本轮只是换成更贴合玻璃质感的薄纱）。
> 真正有区分度、也是"死黑压抑"真正来源的是 **`bg-black/80`** 那一行：**51 → 244**。
> 两条都留在断言里，是为了把"哪条有区分度、哪条没有"这件事**写在证据里**而不是含糊过去。

**交叉验证（两套独立方法，结论一致）**
计算样式只能说明"声明了什么"，为了确认"**实际渲染成了什么**"，又对 4 张取证截图做了**像素级采样**（8×6 网格，按 sRGB 相对亮度统计）：

| 截图 | 亮度中位数 | 采样点中"近黑(<80)"的个数 | 最暗角点示例 |
|---|---|---|---|
| `before-modal-black.png` | **132** | **24 / 48** | `rgb(39,39,40)`、`rgb(19,32,48)` |
| `after-modal-black.png` | **244** | **1 / 48** | — |
| `before-modal-slate.png` | 255 | 0 / 48 | （全白） |
| `after-modal-slate.png` | 239 | 0 / 48 | — |

`before-modal-black.png` 有一半采样点落在近黑区间（另一半是被兼容层刷白的弹窗卡片本身），
与计算样式给出的"合成白底亮度 51"完全吻合 —— **两套方法互相印证，结论可靠**。

## 3. 四个改造区域

### 3.1 全局设计令牌与背景光影重构 —— `src/index.css`

**① 钛晶明亮背景（Titanium Bright Mesh）**
在 `body, #root` 上叠 **8 层** `background-image`（自上而下）：

| 层 | 内容 | 尺寸 |
|---|---|---|
| ① | 晨曦微光粒子（点阵，`radial-gradient`） | 24px |
| ②③④ | 微晶六边形全息透光底网（0° / 90° / 60° 三向线） | 48px |
| ⑤⑥⑦ | 环境景深漫反射光晕（天青 / 晨曦金 / 靛蓝三个大椭圆） | auto |
| ⑧ | 钛晶明亮渐变底（`#F8FBFF → #F1F7FE → #F7F4FF`） | auto |

全部 `background-attachment: fixed`，滚动时层次稳定。

**② 释放背板**：新增 `/* 0) */` 规则，把页面级外壳的 `bg-[#f8fafc]` / `bg-[var(--page-bg)]` 计算背景置为透明 —— 这是"死白纸"的根治。

**③ 游戏级悬浮磨砂卡**：`.glass-card` 与新增 `.hud-card` 双层体系。
`.hud-card` = 96%→86% 白渐变 + `blur(16px) saturate(150%)` + 内发光 + 1px 金/青描边 + hover 上浮 3px + 顶部金→青 2px 能量细线。

> **性能取舍**：`.glass-card` 被 `CockpitDashboardView` 当作整页容器复用，若用 16px 模糊会把整页纳入 backdrop root、拖垮滚动性能，
> 因此**按面积分级**：整页级 `.glass-card` 用 12px，小面积 `.hud-card` 用 16px。

**④ 恢复光影阶梯**：把旧 CSS"一律压平"的三条 `!important` 换成 **6 级阴影阶梯 + 圆角阶梯 + 呼吸式 ping**。
同时**保留**原有"浅底 + 深字，对比度 ≥ 4.5:1"的语义重映射层（铁律不能破）。

**⑤ 修复既有缺陷**：补上 `@keyframes digital-human-breath`、`@keyframes avatar-eyes-blink` 与 `.avatar-eyes`
（`transform-box: fill-box` 让眨眼绕自身中心）—— 这两个动画此前**只有引用、没有定义**。

**⑥ 新增游戏化样式类**（18 个）：
`.hud-card` `.chip-gold` `.chip-cyan` `.bubble-frost` `.bubble-frost-user` `.hud-bar` `.btn-gold` `.icon-tile-gold`
`.fx-shimmer` `.fx-hex` `.fx-particles` `.fx-bloom` `.hud-halo` `.hud-pedestal`
`.flow-line(-slow/-fast)` `.flow-glow` `.pulse-ring(-2/-3)` `.timeline-scroll/-node/-dot/-label`
`.wave-bar-1..5`，以及 `@media (prefers-reduced-motion: reduce)` 降级块。

> **踩坑（已写进代码注释）**：Tailwind v4 的 utilities 位于 `@layer utilities`，而 `index.css` 里的自定义类**不在任何 layer**，
> 因此**无 layer 的作者样式永远压过 Tailwind 工具类**。后果：`.fx-shimmer` / `.fx-hex` / `.hud-pedestal` 一旦声明 `position`，
> 就会盖掉宿主元素上的 `absolute` / `relative`。这三个类**刻意不声明 `position`**。

### 3.2 AI 助手升级为"次世代专家剧场" —— `DigitalHumanAvatar.tsx` + `AiAssistantView.tsx`

- **角色大立绘半身融入**：把小圆头像换成 **286px（sm 322px）剧场舞台**：
  晨曦光晕 `.fx-bloom` → 微晶六边形底网 `.fx-hex` → 晨曦微光粒子 `.fx-particles` → **3 环同心呼吸脉冲** →
  全息光环 `.hud-halo` → **立绘本体**（保留三套人设 SVG 原样）→ 全息基座 `.hud-pedestal` → 声波仪。
  立绘底部用 `mask-image: linear-gradient(180deg, #000 64%, rgba(0,0,0,.40) 87%, transparent 100%)` 渐隐融入基座。
  脉冲环颜色随状态切换：说话=金、聆听=翠绿、待机=天青。
- **呼吸动画**：说话时 1.8s 周期、待机 3.5s 周期（`digital-human-breath`）。
- **金色动态音频波形仪** `WaveformHUD`：可复用组件，说话/聆听时 24 根金→青渐变柱律动（`waveform-bounce`），
  并挂 `data-testid` / `data-active` / `data-bars` 供探针取证（**这也是让"看起来有"变成"可复核"的关键**）。
- **游戏化交互胶囊**：跟进问题、快捷指令统一为 `.chip-gold` / `.chip-cyan` 金边发光胶囊（`border-radius: 999px`），带小图标引导与 hover 流光。
- **微透游戏对话气泡**：`.bubble-frost` / `.bubble-frost-user`。
- **操作底栏拟物游戏化**：`.hud-bar` 磨砂胶囊操作条；录音区加 10 根实时律动柱；麦克风与发送按钮改胶囊形。

### 3.3 驾驶舱升级为"全景数字孪生智能沙盘" —— `CockpitDashboardView.tsx`

**全部程序化生成，零外部资源**（新增 457 行）：

- **场景化大底图 `TwinBackplate`**：程序化 SVG 全景 —— 晨曦天空 + 破晓日光晕、两道山脊、透视地坪网格、
  主厂房、次厂房、3 座立式储罐、塔架（含虚线拉索）、管廊、绿化。
- **流动光轨 `TwinFlowRoutes`**：两条 SVG 路径，金色=设备巡检、天青=物料输送，用 `stroke-dasharray` + `flow-dash`
  让光点沿线流动，并叠 `flow-glow` 发光。
- **呼吸脉冲地标**：16 个设备锚点，每个含 2 环同心 `pulse-ring`（颜色随设备状态：运行/预警/故障/检修/待机/报废）。
- **悬浮情报卡**：右侧 `.hud-card` 浮层，含设备名/编号/车间、状态芯片、三宫格（健康度按阈值变色 / 重要度 / 下次巡检）、
  金→青健康能量条、`.timeline-scroll` 时光长卷（**设备投产 → 历次技改 → 今日智能态**）、节点详情面板。
- **语音播报**：原生 `speechSynthesis`（`zh-CN`，零依赖），失败静默降级。

> **踩坑（已写进代码注释）**：`pulse-ring` 用 `animation` 动 `transform: scale()`，而 Tailwind 的 `-translate-x-1/2` 也是 `transform` ——
> 两者会互相覆盖。因此锚点与脉冲环**一律用 `left/top` + 负 `margin` 居中**，绝不用 translate 工具类。

### 3.4 近黑遮罩统一改为明亮薄纱 —— `src/index.css` `/* 1.1 */`

```css
[class*="bg-black/"].fixed.inset-0,
[class*="bg-slate-900/"].fixed.inset-0,
[class*="bg-slate-950/"].fixed.inset-0 {
  background-color: rgba(230, 239, 250, 0.62) !important;
  backdrop-filter: blur(10px) saturate(140%);
}
```

只命中 `fixed inset-0` 的全屏遮罩，**不会误伤**徽章、缩略图上的 `bg-black/60` 蒙层。
覆盖全项目约 40 处弹窗遮罩（工单、隐患、知识库、备件、作业指引、视频分析…）。

## 6. 回归与遗留

### 6.1 诚实局限

1. **"手绘高清场景大图"实际是程序化 SVG 全景，不是写实手绘大图。**
   原方案写的是"工业数字孪生园区/车间明亮手绘高清场景大图"，但本项目**不允许引入任何外部图片/模型/纹理/字体资源**
   （Phase-1 的 3D 改造同样守这条线）。因此沙盘底图是**矢量风格化全景**：厂房、储罐、塔架、山脊都是带渐变的平面几何形，
   **有场景感与层次，但不是照片级写实**。这是本轮最大的一处"目标 vs 约束"折中，特此明示。
2. **无头环境下的 fps 不可测。** headless Chrome 的 rAF 两秒内只产出 0~4 帧，写进报告等于造假，
   因此帧率探针**默认关闭**（需 `UI_FPS=1` 显式开启），真机帧率以 `verify-3d-identity.mjs` 的 GPU 模式为准。
3. **`.glass-card` 整页复用处的模糊只给 12px。** 面积越大 backdrop-filter 越贵；若后续有真机性能反馈，
   可进一步把整页级容器换成纯渐变（不模糊）。

### 6.2 本轮修掉的脚本缺陷（都是我自己的验收工具的问题，不是产品问题）

| # | 缺陷 | 后果 | 修法 |
|---|---|---|---|
| 1 | 遮罩取证放在遍历的**最后一个视图（3D 场景）**上，点一个该页根本不存在的"查看台账"按钮 | `candidateCount` 恒为 0，取证失败、断言假红 | 改为固定触发点：工单详情抽屉（`bg-black/80`）+ 驾驶舱 KPI 下钻（`bg-slate-900/40`） |
| 2 | 遮罩探针用正则抠 `rgb()` 数字 | 旧版遮罩计算值是 **`oklab(0 0 0 / 0.8)`**（Tailwind v4 的 `color-mix` 在 Chrome 下落到 oklab），正则匹配不到 → 把"近黑"误判成"不黑" | 改用 **canvas 合成**取色，格式无关；并改用"合成白底后的感知亮度"判定 |
| 3 | `verify-3d-identity.mjs` 的 `waitFor` **不自动包 `!!()`**，我新写的表达式返回 DOM 节点 | 节点经 `returnByValue` 序列化成 `undefined`，永远等不到 → 白白超时 60s | 表达式自己返回布尔值，并在代码里写明这条约定 |
| 4 | 同脚本用固定 `sleep(2500)` 后查登录表单 | Vite dev 冷编译时页面白几秒，被误判成"已登录"→ 跳过登录 → 报"未能进入 3D 视图"（看起来像功能坏了） | 改为轮询等首屏（登录表单 或 `main`），登录后再等 `main` |
| 5 | 同脚本 `SHOT_DIR` 硬编码为 `docs/equipment3d-shots` | 跑回归会把 **Phase-1 已验收的 60+ 张交付截图**覆盖掉，一旦截出白图就把好证据毁了 | 支持 `E3D_SHOT_DIR` 重定向；本轮回归输出到 `scratch/3d-identity-post-hud/` |

> 第 3~5 条**解释了此前 `E3D_GPU=1` 那一轮报 `ok:false`、`eq-101.png` 全白的原因**：
> 是脚本跑早了/等错了，**不是 3D 被改坏**。本轮已用同脚本 headless 模式拿到 **23/23 通过 + 16/16 截图互不相同**，
> 该疑点**已闭环**。

**关键环境约定**（踩过的坑，写下来避免重犯）

- **会话是内存态**：登录后 `localStorage` 仍为空，**任何整页刷新都会掉登录** → 自动化必须在 SPA 内点导航（`#nav-tab-<key>`），不能 `Page.navigate`。
- **Vite dev 冷编译**：首次访问某视图要现场 transform，页面会白几秒 → 一律轮询等首屏，不用固定 sleep。
- **无 layer 的 CSS 压过 Tailwind 工具类** → 自定义类不要声明 `position`。
- **`transform` 动画会覆盖 `-translate-*`** → 被动画的元素用 `left/top` + 负 margin 居中。

# 补充：SOP 页（作业指引）字号/密度回归修复

> 本节是对本次视觉重构的**自查修正**。重构整体方向保留，但 `ProceduresView.tsx`
> 在"密集化"过程中被压得过头，导致该页可读性明显低于其它页，用户直接提出质疑。

## 1. 问题

用户反馈（附两张截图对比）：

> "一张图片怎么内容缩小了这么小。这看得清吗？大小最起码改成第2张图片的样子。"

图 1 = **检修作业指引（SOP）页**，图 2 = **点巡检作业页**。诉求：SOP 页至少达到点巡检页的可读性。

## 2. 定位过程（先排除误判）

| 检查 | 结论 |
|---|---|
| 两张截图里**同一个 `PageHeader` 组件**的标题文字行高 | **都是 23 px** → 排除浏览器缩放差异 |
| 两张截图的正文行高中位数 | 17 px vs 18 px → **字号本身只差一点点** |
| 页面宽度上限 | 两页都是 `max-w-[1440px]`（`App.tsx`，仅 `cockpit` 是 1920）→ 排除宽度 |
| 是否存在 `transform: scale` / `zoom` | 无 |
| `git diff --stat HEAD -- src/components/ProceduresView.tsx` | **+121 / −172** ← 真凶 |

即：**真正的差距是间距/内边距/对比度，不是单一字号**。而 `ProceduresView.tsx`
被本轮重构做了一次系统性"缩小一号"的改写。

### 2.1 被缩小的规律（从 diff 中提取）

| 原（HEAD） | 现（重构后） |
|---|---|
| `text-xs` | `text-[11px]` |
| `text-sm` | `text-xs` |
| `text-lg` | `text-base` |

### 2.2 字号普查（关键证据）

| | `text-[10px]` | `text-[11px]` | `text-xs` | `text-sm` | `text-base` | `text-lg` | `text-xl` |
|---|---|---|---|---|---|---|---|
| 修复前 | 10 | 9 | 22 | 5 | 1 | 1 | 0 |
| **`git HEAD`（重构前）** | 5 | 7 | **32** | 7 | 0 | 1 | 1 |
| `InspectionView`（点巡检，目标） | 7 | 11 | **31** | 11 | 2 | 0 | 1 |

→ **重构前 SOP 页原本就和点巡检页是同一套字号尺度**，是本次重构把它压小的。
（这是本节最有价值的一条：修复方向不是"发明一个更大的尺度"，而是"还原回重构前的尺度"。）

### 2.3 顺带查出一个真 bug

详情卡原来是：

```diff
- <div className="card-industrial bg-white border border-slate-200 p-5 border-l-4 border-l-blue-600 shadow-xs rounded-xl">
+ <div className="p-4 border-l-3 border-l-blue-500 rounded-lg">
```

`border-l-3` **不是 Tailwind 默认的 border 宽度**（全仓库其它 6 处都用 `border-l-4`），
所以修复前这张卡**根本没有左侧蓝色竖条**，也丢了白底/描边/阴影。
（截图证据：`scratch/sop-before.png` 里详情卡左侧是平的。）

## 3. 修法

脚本：`scratch/apply-typography-fix.py` —— **72 组整串替换，每组断言出现次数，任一不匹配就整体中止、不写盘**。

原则：**只还原"尺寸尺度"，保留本轮 HUD 的配色语言**（浅色填充、圆角卡片、左侧色条等设计意图不动）。

同时修掉 `border-l-3`，还原为 `card-industrial … p-5 border-l-4 border-l-blue-600 rounded-xl`。
