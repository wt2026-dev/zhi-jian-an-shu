# 安全可信证据链（等保 2.0 视角）

> 用途：把系统**已落地**的安全与可信控制逐项列出，每条锚定到具体代码文件与回归测试，
> 供等保测评/评审追问时按图索骥。只写有代码与测试背书的事实，不写规划项。
> 更新时间：2026-10-19。

## 1. 身份鉴别（等保：身份鉴别 / 口令策略）

| 控制点 | 实现 | 证据 |
|---|---|---|
| 密码不可逆存储 | `bcryptjs` 哈希 | `package.json`（bcryptjs ^3.0.3）、`tests/auth-password-hardening.test.ts` |
| 登录凭证 | JWT（`jsonwebtoken`），Bearer 鉴权 | `src/server/services/authService.ts`、`tests/auth.test.ts` |
| 登录防爆破 | 连续失败 5 次锁定 15 分钟（进程内滑动窗口计数） | `src/server/middleware/rateLimit.ts`（checkLoginBruteForce / recordLoginFailure / recordLoginSuccess）、`tests/auth-baseline.test.ts` |
| 会话管理 | refresh 端点独立于登录；登出端点 | `src/server/routes/auth.ts`（/login /logout /refresh /me） |

## 2. 访问控制（等保：访问控制）

| 控制点 | 实现 | 证据 |
|---|---|---|
| 全局鉴权基线 | `globalAuthGuard` 默认拒绝 + 端点白名单，挂在全部业务路由之前 | `src/server/middleware/auth.ts`、`src/server/index.ts`（装配顺序见下） |
| CSRF 兜底 | 写方法（POST/PUT/PATCH/DELETE）校验 Origin/Referer | `src/server/index.ts`（helmet 之后的 CORS 兜底段） |
| 跨域白名单 | CORS 可配置白名单，非全放开 | `src/server/index.ts` |
| 安全响应头 | `helmet`（CSP 白名单等） | `src/server/index.ts`（createApp 首个中间件） |
| 角色权限 | 巡检创建等敏感操作校验角色（主管/安全监护/管理员/技师） | `src/server/controllers/inspectionController.ts`、`src/server/middleware/auth.ts` |

## 3. 安全审计（等保：安全审计）

| 控制点 | 实现 | 证据 |
|---|---|---|
| 操作审计 | `addAuditLog`：动作类型/模块/详情/状态/元数据落库 | `src/server/services/auditService.ts`，调用点遍布各 controller |
| AI 调用审计 | 每次模型调用记录模型/提示词版本/输入摘要/审核状态/成败 | `src/db/repositories/aiAnalysisLogRepository.ts`（recordAiCall） |
| 请求级链路追踪 | 每请求生成 UUID traceId，注入响应头 `X-Trace-Id`，贯穿访问日志与错误日志 | `src/server/middleware/traceId.ts`、`tests/logger-traceId.test.ts` |
| 结构化日志 | 服务端 JSON 结构化输出 + 按大小轮转落盘 `logs/`（5MB×5），生产静默 debug/info | `src/utils/logger.ts`、`tests/logger-traceId.test.ts` |
| 审计不可绕过 | 审计走 DB 落库而非内存（重启不丢）；工单日志单一数据源（详情/时间线同表） | `tests/work-order-log-single-source.test.ts`、提交 14abf1e |

## 4. 入侵防范 / 资源控制（等保：入侵防范、资源控制）

| 控制点 | 实现 | 证据 |
|---|---|---|
| API 全局限流 | 每 IP 600 次/分钟（/api/v1/*），自研滑动窗口 | `src/server/middleware/rateLimit.ts`（globalLimiter）、`tests/rate-limit-sweep.test.ts` |
| AI 专属限流 | 60 次/分钟（/api/v1/ai/*），保护上游预算 | 同上（aiLimiter） |
| 登录专属限流 | 20 次/分钟，叠加防爆破锁定 | 同上（authLimiter） |
| 伪造来源防护 | 伪造 `X-Forwarded-For` 不影响限流计数 | `tests/ip-trust.test.ts` |
| Store 自清理 | 限流窗口超阈值自动清扫，防内存膨胀 | `tests/rate-limit-sweep.test.ts` |
| 上传限制 | JSON/urlencoded body 2MB 上限 | `src/server/index.ts` |

## 5. 数据完整性 / 容错（等保：数据完整性、数据备份恢复）

| 控制点 | 实现 | 证据 |
|---|---|---|
| 业务编号唯一性 | 工单/作业票/巡检编号：进程内互斥 + 跨副本撞号自动重试（UNIQUE 约束兜底） | `src/db/dailyNo.ts`（withNumberLock / withDailyNoRetry）、`tests/daily-no-retry.test.ts` |
| 乐观并发控制 | 工单/作业票 update 带 version 校验，冲突抛 VersionConflictError | `src/db/repositories/workOrderRepository.ts`、`src/db/repositories/shared.ts` |
| 数据库双适配器 | PGlite（嵌入式）与 PostgreSQL（pg.Pool）同接口，生产默认 PG、外部库不可达 fail-fast 拒绝静默降级 | `src/db/db.ts`（DatabaseAdapter / buildPostgresUrl） |
| 数据迁移工具 | PGlite→PostgreSQL 全表迁移脚本（外键序 + 计数校验） | `scripts/migrate-pglite-to-postgres.ts` |
| 资产完整性 | 关键 GLB 资产 SHA256 清单 + glTF 魔数校验，接入 pre-commit 门 | `assets-manifest.json`、`scripts/verify-assets.mjs`、`scripts/git-hooks/pre-commit` |

## 6. 剩余风险声明（诚实边界）

| 风险 | 现状 | 触发条件与对策 |
|---|---|---|
| 限流为进程内存储 | 单实例部署下完全有效 | 多副本扩容前需迁 Redis（README 已声明为规划项） |
| 登录锁定为进程内计数 | 单实例下有效 | 同上 |
| PGlite 嵌入库 | 默认开发/演示用；生产可切真 PG（DB_TYPE/DATABASE_URL） | 切换步骤见 README-DEPLOY；迁移脚本已备 |
| 自签 TLS | 生产 :3000 已启用自签证书 | 正式环境换 CA 证书即可，代码路径不变 |

## 7. 中间件装配顺序（证据：src/server/index.ts createApp）

```
helmet → CSRF兜底(Origin/Referer) → cors → body限制(2MB)
→ traceId → requestLogger → /health /ready
→ /uploads 静态 → /api/v1/ globalLimiter → /api/v1/ai/ aiLimiter
→ globalAuthGuard(默认拒绝+白名单) → 业务路由 → globalErrorHandler
```
