## 2. 详细加固方案

### 任务 1：修复伪乐观锁（真正的 CAS 并发控制）

#### 问题剖析
原代码中 `work_orders` 和 `safety_permits` 的 `UPDATE` 语句仅使用 `WHERE id = $N`，`version` 仅在应用层做单纯的自增，多个并发请求读到相同版本后并发写入会互相覆盖（后写覆盖先写），无法提供有效的并发互斥保护。

#### 改造方案
1. **数据访问层 CAS 保护**：
   - 在 `WorkOrderRepository.update` 与 `SafetyPermitRepository.update` 中引入可选参数 `expectedVersion?: number`。
   - 当调用方显式传入版本时，SQL 变更为：
     ```sql
     UPDATE work_orders SET ..., version = $NEXT_VER, updated_at_dt = CURRENT_TIMESTAMP
     WHERE id = $ID AND version = $TARGET_VER;
     ```
   - 执行后检查受影响行数：若 `rowCount === 0`，查出最新版本并抛出强类型异常 `VersionConflictError(message, currentVersion, expectedVersion)`。
2. **控制器统一异常捕获与响应**：
   - 在工单派发、接单、完工、验收、通用状态流转，以及作业票审批、注销闭环等关键状态流转接口中，捕获 `VersionConflictError` 并返回 HTTP 409：
     ```json
     {
       "code": "VERSION_CONFLICT",
       "message": "工单数据已被其他人更新，请刷新最新状态后再试。"
     }
     ```
3. **版本冲突与状态互斥优先级对齐**：
   - 控制器预检查中，优先校验 `if (version !== undefined && order.version !== version)`，后校验状态机允许性，防止并发到达的过期请求被误报为 400 `STATE_MUTEX_ERROR`。
4. **向后兼容保障**：
   - 未显式传递 `version` 的普通非并发更新请求（如后台元数据自动刷新），继续执行常规 `WHERE id = $ID` 更新，版本正常递增，系统行为完全向后兼容。

### 任务 2：时间戳 ISO-8601 标准化

#### 问题剖析
服务端多处日志落库与状态时间记录使用了 `toLocaleString("zh-CN")` 或 `toLocaleDateString`，产生形如 `"2026/9/13 14:05:00"` 的本地化字符串。该格式存在三大弊端：时区丢失、字符串排序失真、无法直接用于范围索引查询。

#### 改造方案
1. **统一写入格式**：
   - 梳理服务端的 11 处时间戳写入，全部改为标准 UTC ISO-8601 字符串：`new Date().toISOString()`（如 `2026-09-13T09:44:01.123Z`）。
   - 涉及：工单创建/派单/接单/完工/验收时间、作业票申请/审批/关闭时间、工单流转日志与系统审计日志、派单调度日志、通知创建时间等。
2. **向前兼容读取与查询**：
   - 针对看板与报表中基于字符串前缀匹配的查询（如按天统计 `LIKE '2026-09-13%'`），补充正则与多条件兼容逻辑，同时命中历史格式与标准 ISO 格式：
     ```sql
     (accepted_by_inspector_at LIKE '2026-09-13%' OR accepted_by_inspector_at LIKE '2026/9/13%')
     ```
3. **数据库历史数据平滑迁移**：
   - 新增迁移脚本 `src/db/migrations/022_timestamp_normalize.sql`，执行历史中式时间戳的格式转换，保障升级过程中旧数据正常检索。

### 任务 3：AI 设备遥测指标 6 维口径统一

#### 问题剖析
设备遥测表与种子数据已扩充为 7 个维度，但 `aiForecastController.ts`（设备劣化与健康预测）仅处理了 4 个维度（`temperature`, `vibration`, `current`, `loadRate`），漏掉了关键的 `pressure`（管路压力）与 `rpm`（转速），导致健康度评分与大模型研判输入存在信息截断。

#### 改造方案
1. **聚合指标扩展**：
   - 在 `metrics` 对象中补齐全部 6 维关键指标：
     ```typescript
     metrics: {
       temperature: calcStats(recent.map(r => r.temperature)),
       vibration: calcStats(recent.map(r => r.vibration)),
       current: calcStats(recent.map(r => r.current)),
       pressure: calcStats(recent.map(r => r.pressure)),
       loadRate: calcStats(recent.map(r => r.loadRate)),
       rpm: calcStats(recent.map(r => r.rpm)),
     }
     ```
2. **大模型 Prompt 对齐**：
   - 将 6 维统计数据（均值、最大值、方差）与工业标准阈值注入提示词（如压力警戒线 2.5 MPa、转速上限 3000 r/min），指导 LLM 输出更精确的多维度劣化成因分析。
3. **本地规则引擎降级对齐**：
   - 离线/降级模式下同步加入压力超标（`> 2.5 MPa` 扣 15 分）与转速超限（`> 3000 r/min` 扣 12 分）的健康评分扣减规则，确保断网或外部 API 异常时画像分析不失真。

### 任务 4：主键与流水号并发防碰撞

#### 问题剖析
部分流水号使用 `log-${Date.now()}` 或截断过短的随机数，高并发测试或批量导入时容易在毫秒级内产生重复主键冲突导致事务回滚。

#### 改造方案
1. **强化唯一性算法**：
   - 将各日志与实体的主键生成逻辑统一规范为：
     ```typescript
     `log-${Date.now()}-${Math.random().toString(36).slice(2, 10)}`
     ```
   - 保证毫秒级时间戳 + 8位 Base36 随机熵，并发碰撞概率降至极限微小（`< 10^-12`）。
2. **长度约束安全保障**：
   - 新格式字符串长度约 24~28 字符，严格满足数据库 Schema 定义的 `VARCHAR(64)` 约束，无溢出风险。
