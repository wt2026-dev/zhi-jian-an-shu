## 四、连带发现并修复的 2 个既有 bug（P1-4 过程中发现）

1. **登录防爆破锁定从未生效（安全级）**：`recordLoginFailure` 的重置条件 `record.lockedUntil <= now` 在未锁定（lockedUntil=0）时恒为真，每次失败都把 count 重置为 0——连续失败计数永远到不了 5，`IP_LOCKED` 429 响应虽在契约中但**从未可能触发**。已修复为仅在"锁定已设置且已过期"时重置计数，并补锁定语义测试。此为恢复既有 API 契约声称的行为，非契约变更。
2. **清扫顺序导致限流失效（自引入当天发现当天修复）**：初版清扫写在 `set()` 之后，新 key 的 timestamps 为空数组被误判"窗口外"删除——10000 上限后每个新 key 被立即删掉且计数对象孤立，对应请求完全脱离限流。已改为**先清扫后插入**（探针定位：i=10000 起 `has-current=false`、size 恒为 10000）。测试断言"满载后新 key 计数仍在"锁定此行为。
