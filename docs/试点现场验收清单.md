# 试点现场验收清单（单工厂 · 单车间）

> 定位：本清单供现场验收执行使用，明确区分三类状态——
> **[代码已实现]** = 代码与测试证明；**[测试通过]** = 自动化测试覆盖；**[待现场验证]** = 必须由现场执行确认，本仓不代为声称。
> 配套文档：《生产差距清单-试点部署.md》（差距与整改）、README-DEPLOY.md（部署与备份操作）。

## 1. 账号与角色确认（现场执行）

- [ ] **[待现场验证]** 按最小权限建真实账号：至少 1×admin、1×manager（车间主管）、2×technician、1×inspector、1×operator（报修）。首启用 `SEED_MODE=minimal` 后由 admin 建号，绝不复用演示口令。
- [ ] **[待现场验证]** 首次登录逐账号改密确认（强制改密策略开启）。
- [ ] **[待现场验证]** 越权抽查：用 operator 登录尝试派单/验收接口（应 403 且审计留痕）；用 technician 尝试验收（应 403）。
- [ ] **[待现场验证]** 审计查询：admin 查 `/api/v1/audit-logs` 能看到上述越权拒绝记录。

## 2. 业务闭环端到端验收（现场执行，覆盖真实设备样本）

主链路：**报修 → 作业票双人会签 → LOTO 上锁 → 派工 → 检修 → 完工 → 质检验收 → 归档**

- [ ] **[待现场验证]** 选取 ≥2 台真实设备（建议 1 台关键机 + 1 台一般机），由 operator 报修创建工单。
- [ ] **[待现场验证]** 作业票：两名授权人分别会签（测试单账号无法自会签）。
- [ ] **[待现场验证]** LOTO：领锁/上锁/解锁/归还全流程，含"未全部解锁不得验收"联锁触发一次。
- [ ] **[待现场验证]** 派工乐观锁：两名 manager 同时派同一工单，后提交方收到冲突提示且无脏写。
- [ ] **[待现场验证]** 验收驳回→返工→复验一次（状态机不允许跳步的路径各触发一次）。
- [ ] **[测试通过]** 状态机防跳/越权/并发冲突（automation 已覆盖：business-loop、safety-interlock-e2e、workorder-rbac、optimistic-lock 等 159 文件 / 1692 用例基线，2026-10-20 实测）。
- [ ] **[待现场验证]** AI 能力抽查：诊断建议、派单推荐可降级运行，降级时响应明确标注 `degraded`，不阻塞人工流程。

## 3. 故障演练（现场执行）

| 演练项 | 期望 | 状态 |
|---|---|---|
| 数据库不可用 | 停 PG 后 `/ready`=503、`/health` 保持 200、业务请求 5xx 不崩溃；恢复后 `/ready` 回 200 | [测试通过] pilot-resilience 4 项；**[待现场验证]** 真实 PG 停启 |
| 服务重启 | systemd/容器重启后自动拉起，数据无损，迁移幂等跳过 | **[待现场验证]** |
| 网络中断（终端侧） | 现场终端断网时操作有明确失败提示，恢复后可重试，不产生重复工单 | **[待现场验证]** |
| 备份恢复演练 | 运行 `node scripts/restore-drill.mjs <快照>` 于隔离目录，输出 PASS | [测试通过] 脚本+测试；**[待现场验证]** 现场演练一次并留记录 |
| 备份调度 | cron/systemd-timer 每日执行 `scripts/backup.sh`（退出码非 0 告警），保留策略按现场定 | [代码已实现] 脚本与保留策略；**[待现场验证]** 调度与告警通道接通 |

## 4. 备份与 RTO/RPO 声明边界

- **[代码已实现]**：一致性快照、快照自校验、隔离恢复演练、保留轮换（`BACKUP_KEEP_N`）。
- **[待现场验证 / 由现场决策]**：备份目标位置（本机外挂盘/NAS/异地）、备份频率、告警通知渠道、加密需求。
- 本仓**不声称**满足任何具体 RTO/RPO 数值；恢复耗时以现场演练实测为准。

## 6. 放行判据

进入试点运行须同时满足：第 0 节部署前提全部达成；第 2 节主链路演练全过；第 3 节数据库不可用/服务重启/恢复演练三项实测通过；第 1、5 节账号与培训完成。任一项未过，标注原因并挂起，不降低判据。
