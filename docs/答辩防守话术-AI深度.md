# 答辩防守话术：AI 深度

> 用途：应对"你们的 AI 护城河在哪 / 这不就是调 API 吗 / 20 项能力是不是凑数"类提问。
> 原则：**不吹能力数量，讲治理闭环**。评委要的不是"你们 AI 多"，而是"你们懂不懂 AI 落地"。
> 所有说法均有代码支撑（src/server/services/aiModelRouter.ts、aiClient.ts、aiReviewService.ts、auditService.ts）。
> 口径统一（2026-09-13）：AI 能力共 **20 项**（按 /api/v1/ai/* + legacy 去重端点计），其中 **7 项支持 SSE 流式**，与 README 一致。

---

## 一、30 秒主话术（背诵版）

> "我们的 20 项 AI 能力背后，不是 20 个孤立的接口调用，而是一套统一的 AI 治理框架。
> 第一，**多模型路由**：模型配置可管理、API Key 加密存储、调用失败会在主备模型间自动切换并写审计日志，而不是让用户看到报错；
> 第二，**降级不伪造**：任何 AI 调用失败，系统都标记 degraded 并落到规则引擎兜底，绝不生成一个没有依据的假结果——这在检修场景是底线；
> 第三，**生成内容进审核台**：检修方案、风险评估、智能报告都要经人工审核闸才能生效，且回答带知识库溯源。
> 所以我们的重点不是'AI 能做什么'，而是'AI 在工业场景里怎么被信任、怎么受控'。在设备检修这个场景，这比能力数量重要得多。"

## 二、15 秒极简版（时间不够时用）

> "我们做的不是堆 API，而是 AI 治理闭环：模型可配置可切换、失败自动降级且不伪造结果、生成内容人工审核 + 知识溯源。信任和可控，才是工业 AI 的核心。"

## 三、评委追问拆解

### Q1：这不就是调 API 吗？换谁都行。

**回答**：
"调 API 是能力数量，我们做的是能力之外的三件事：
① **容错**——多模型路由，主模型超时/断连/5xx 自动切换备选模型，切换事件写审计（AI_MODEL_FAILOVER），健康状态回写数据库，管理端能看到每个模型的实时健康度；
② **密钥安全**——模型 API Key 在数据库里是 AES-256-GCM 加密存储，密钥由服务端 JWT_SECRET 派生，前端零凭证；
③ **结果治理**——生成内容登记审核台，人工过闸后才算数。
这三层才是工作量所在。"

### Q2：你们 AI 的护城河在哪？

**回答**：
"护城河是**业务闭环 + 数据回流**，不是模型本身：
① 生成内容不是一次性的——检修方案、报告进 `ai_generation_reviews` 人工审核台；
② 审核通过的优秀内容可以沉淀进知识库（`ai_knowledge_contributions`），RAG 检索会引用它，形成'AI 产出 → 人工把关 → 知识沉淀 → 再被 AI 引用'的飞轮；
③ 全链路审计：每次 AI 调用、每次降级、每次失败切换都有审计记录，可追溯。
模型会换代，但这个治理闭环是系统级的。"

### Q3：AI 结果错了怎么办？工业场景敢用吗？

**回答**：
"三个防线：
① **降级不伪造**——调用失败宁可走规则引擎并打 degraded 标记，也不给编造的结论；
② **人工审核闸**——检修方案、JSA 风险评估、报告类内容必须经审核台人工确认；
③ **溯源**——知识问答类回答携带知识库来源（knowledgeSources），用户能查证。
我们的定位是'AI 辅助决策'，不是'AI 替代判断'，责任人永远是人。
另外，知识检索本身是**混合 RAG**：DashScope text-embedding-v3 生成 1024 维向量做语义召回，与关键词打分做 RRF 融合，只返回已审核（approved）内容；embedding 服务不可用时自动回退关键词检索，检索能力永不中断。"

### Q4：20 项能力里哪些是真有业务逻辑的？哪些就是调模型？

**回答**（诚实分层，评委反而认可）：
"我们内部也分了三层：
① **纯规则/业务逻辑层**——辅助派单（技能匹配 + 工作负载排序）、报警关联分析、测点异常判定，这些是确定性的业务代码，不依赖模型；
② **AI 生成层**——故障诊断、检修方案、根因分析、巡检报告，走 RAG + 大模型生成，配合审核闸；
③ **多模态层**——视觉缺陷识别，调用 qwen-vl 做图像理解。
我们坦诚：模型能力是采购的，系统能力（路由、降级、审核、审计、知识回流）是自研的，后者才是工作量。"

### Q5：现场没网 / 没配 API Key，演示会不会翻车？

**回答**：
"不会。所有 AI 接口都是**优雅降级**设计：未配置密钥、调用超时、模型不可用时，自动切换到规则引擎结果并标记 degraded，页面正常展示、流程不中断。这本身就是我们想演示的能力——工业现场的 AI 必须容忍不可用。"

## 四、能力分层清单（诚实版，答辩可带这张表）

| 层级 | 能力 | 底层实现 | 深度定位 |
|---|---|---|---|
| 业务逻辑层 | 辅助派单 | 技能匹配 + 工作负载排序（确定性代码） | 自研 |
| 业务逻辑层 | 报警关联分析 | 规则引擎 + 时序特征 | 自研 |
| 业务逻辑层 | 巡检打卡判定 | 测点规则判定 | 自研 |
| AI 生成层 | 故障诊断 / 根因分析 | RAG + qwen-plus 生成 | 自研框架 + 采购模型 |
| AI 生成层 | 检修方案 / 风险评估(JSA) | 生成 + 人工审核闸 | 自研框架 + 采购模型 |
| AI 生成层 | 智能报告 / 巡检报告 | 生成 + 审核闸 + 溯源 | 自研框架 + 采购模型 |
| AI 生成层 | 知识库 RAG 混合检索 | **向量检索 + 关键词 RRF 融合**：DashScope text-embedding-v3（1024 维）生成向量，pgvector HNSW 索引（生产 PostgreSQL）/ JSONB + 应用层余弦（PGlite）双模式存储；无 Key 时透明回退关键词路径，检索结果携带文章溯源 | 自研框架 + 采购模型 |
| 多模态层 | 视觉缺陷识别 | qwen-vl-max 图像理解 | 采购模型 |
| 支撑层 | 多模型路由 / 降级 / 审计 / 密钥加密 | aiModelRouter + auditService | 自研（核心卖点） |

## 五、AI 治理闭环（三句话讲清）

```
模型调用（多模型路由 + 失败切换 + 审计）
        ↓
生成结果（失败则规则引擎降级，标记 degraded，绝不伪造）
        ↓
内容审核（ai_generation_reviews 人工审核闸：方案/风险/报告）
        ↓
知识沉淀（审核通过 → 知识库贡献 → RAG 检索引用 → 飞轮）
```

## 六、话术纪律（别踩的坑）

1. **别说**"我们自研了大模型"——模型是采购的，说了必翻车。
2. **别吹**"AI 准确率 95%"——没有评测数据支撑的数字是送命题。
3. **别躲**"视觉就是调 qwen-vl"——主动分层承认，反而显得诚实专业。
4. **别承诺**"AI 取代工程师判断"——人永远是责任人，这是安全合规底线。
5. **备好演示兜底**：答辩前确认 API Key 有效，同时准备一条无 Key 的降级演示路径，双保险。
6. **Git 提交历史追问**：若评委关注代码演进或提交历史，主动坦白：**“提交历史做过发布基线整理，原始开发过程完整保留，可现场查看”**，不吹嘘刻意美化的提交历史，重在展示代码演进真实可信与测试基线严谨。
7. **等保合规与演示密码追问**：若被问及等保或演示密码，统一口径：**“系统是参照等保三级规范设计的安全基线；演示环境为保障评审流畅采用独立强密码且默认关闭改密；生产部署必须开启 DEMO_FORCE_PASSWORD_CHANGE，且生产密码通过环境变量注入，演示密码绝不入生产”**，不夸大宣称“严格通过等保三级认证”。
